# 反向剂量：在原本换得过去的状态里把图像路调弱，切换会不会失败

2026-11-09。接 [闭环报告](HIL_MECHANISM_CLOSED_LOOP_REPORT.md)和[修复报告](HIL_MECHANISM_REPAIR_REPORT.md)。

已有的结果只有一个方向：失败格里把动作专家第 12–14 层图像 token 上的 B − A 放大到 2 倍（amp2），切换从 17/90 升到 64/90，两种随机对照只有 21–22。这说明补强这条路**足以**救回切换。还没回答的是另一个方向：在原本能换的状态里把这条路**调弱到自然失败的水平**，切换会不会失败？

## 1. 问题与假设

**问题**：失败格的图像 gap 中途降到起点的约 0.55（试点 0.51–0.71，留出 0.55），成功格约 1.1。把成功格的图像路人为调到同样水平，切换会不会像自然失败那样失败？

**做法**：λ < 1 时，`amp` 臂把 B 的 K/V 向 A 的移动：

K/V ← B + (λ − 1)(B − A)

所以 λ = 0.5 时 B − A 剩一半（≈ 自然失败的水平），λ = 0 时这三层图像 token 上读到的就是 A 的 K/V。

**假设**：
- H1（变淡足以导致失败）：λ = 0.5 让原本能换的状态明显换不过去，而且同样大小的随机扰动不行。
- H2（这条路是必要的）：λ = 0 让大多数切换失败。
- H3（失败的样子和自然失败一样）：调弱引起的失败多半是把旧任务 A 做完（自然失败 59/73 是这样）。

## 2. 臂

| 臂 | 种类 | λ | 层 | 作用 |
|---|---|---|---|---|
| native | native | 1 | — | 不动 |
| wk75 / wk50 / wk25 / wk0 | amp | 0.75 / 0.5 / 0.25 / 0 | 12–14 | B 的图像 K/V 向 A 移动，剩 75% / 50% / 25% / 0 的 B − A |
| wk0all | amp | 0 | 全部 18 层 | 每一层的图像 K/V 都是 A 的（文字 token 仍是 B 的） |
| rnd0 | rand | 0 | 12–14 | 方向随机、每个向量大小等于 wk0 的改动（‖B − A‖） |
| act0 | actrand | 0 | 12–14 | 动作上匹配：native 的动作块每行每组推一把，大小等于 wk0 的动作改动，方向整局固定 |

- 方向种子：rnd0 用 `closed_loop.direction_seed(SW)`，act0 用 `repair.push_seed(SW)`，与前两批相同。
- rnd0 和 act0 的大小都按 wk0（最大的改动）来配，比 wk50 的改动大；拿它们和 wk50 比是偏保守的。

## 5. 读法

第 5 节状态：已冻结（2026-11-09，提交前）。

**只用正式批次的初始布置 2–19。** smoke 只作描述。

**统计**：同闭环（`closed_loop.paired`）。状态按阶段 1 的 SW 分支配对；差的均值和 95% 区间用 bootstrap，按格分层、格内重抽状态，2000 次，种子 0。

**C1 工具核对**（smoke 和正式都要过），`tool_ok` 需要以下全部成立：
1. 每次运行都完成，哈希核对通过，结果能由轨迹重算出来；服务端日志与客户端逐请求一致；
2. 切换步的物理哈希与阶段 1 同一 SW 分支相同；
3. 请求 1 上，干预程序在 λ = 1 时与 `Policy.infer` 的 L∞ 差：中位 ≤ 0.01，最大 ≤ 0.05；
4. native 没有任何 K/V 改动，请求 1 的动作与 λ = 1 相同；
5. 其余臂每次请求的 K/V 改动 ÷ (|λ − 1|·‖B − A‖) 与 1 的差 ≤ 0.001（act0 记录的是它所匹配的 wk0 程序）；
6. act0 每次请求、每行每组的推动大小与 wk0 改动之差 ≤ 1e-5；
7. 除 native 外，每个臂请求 1 的动作块都与 λ = 1 时不同；
8. 实际用的指令都是 B。

**D1 变淡到自然失败的水平**（wk50；成功格 = 试点成功格 + 留出成功格，232 个状态）。下降 = native − wk50，特异性 = act0 − wk50：
- `fade_blocks`：下降区间下界 > 0、下降 ≥ 0.15、特异性区间下界 > 0；
- `fade_weakens`：下降和特异性的区间下界都 > 0，但下降 < 0.15；
- `nonspecific`：下降区间下界 > 0，特异性区间下界 ≤ 0；
- `fade_tolerated`：下降区间上界 < 0.15；
- `unclear`：其余情况。
预测：`fade_blocks`。

**D2 拿掉这条路**（wk0，同样的 232 个状态）。下降 = native − wk0，特异性 = act0 − wk0：
- `necessary`：下降区间下界 > 0、下降 ≥ 0.5、特异性区间下界 > 0；
- `contributes`：同上但 0.15 ≤ 下降 < 0.5；
- `weakly_contributes`：同上但下降 < 0.15；
- `nonspecific`：下降区间下界 > 0，特异性区间下界 ≤ 0；
- `not_necessary`：下降区间上界 < 0.15；
- `unclear`：其余情况。
预测：`necessary`。

**D3 失败的样子**（wk0，同样的格）：native 换成功、wk0 没换成功的状态里，机器人把 A 做完的比例：
- 少于 10 个这样的状态：`insufficient`；
- 比例 ≥ 0.5：`commits_like_natural`；否则 `derails`。
预测：`commits_like_natural`。

**只报告、不作读数**：
- D1、D2 分别在试点成功格、留出成功格上；wk50 引起的失败的样子；
- D4 剂量曲线：试点成功格 + 中间格（72 个状态）上 λ = 1、0.75、0.5、0.25、0 的切换率；
- D5 起点格（t = 0，Goodfire 式定位的闭环对应）：native − wk0、native − wk50、native − act0；
- D6 其余层：试点格上 native − wk0all、wk0 − wk0all；rnd0 的下降；
- 每格每臂的切换数、失败时 A 完成数、换成功用的步数、请求 1 动作变化的中位、请求 1 的图像 gap。

**解读规则**（写在运行前）：
- **D1 `fade_blocks` 且 D2 `necessary` 或 `contributes`**：因果是双向的。把这条路调到自然失败的水平，原本能换的切换就会失败；补回来（闭环、修复批次）就能救。"图像路变淡是中途换不过去的一个原因"可以写成正反两面的证据。
- **D1 `fade_tolerated`，D2 `necessary` 或 `contributes`**：这条路是必要的，但自然水平的变淡本身不足以让切换失败；自然失败还需要别的因素。主张收窄为"补强这条路能补偿失败"。
- **D2 `not_necessary`**：成功格里 B 不靠这条路也能进来（例如第 16 层的文字路）；只能说"补强这条路能救"，不能说它是瓶颈。
- **`nonspecific`**：同样大小的动作扰动也能让切换失败；调弱的效果不能归给这条路的方向。
- **D3 `commits_like_natural`**：人为调弱复现了自然失败的样子（继续做 A）；`derails` 则说明调弱的失败和自然失败不同。
- D5 只说明 t = 0 时这三层是否也必要，与 Goodfire 的开环定位对照；不作读数。

## 7. 风险

- **调弱会不会只是"扰动大了就坏"**：act0 在动作上匹配 wk0，rnd0 在 K/V 上匹配；两者都比 wk50 大。
- **起点格不是读数**：t = 0 时换指令本来就容易，D5 只作对照。
- **留出成功格只有四个臂**：剂量曲线和 rnd0、wk0all 只在试点格上。
