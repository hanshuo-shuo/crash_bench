## 1. 问题与假设

**问题 1（动作匹配对照）**：在闭环检验的五个失败格里，amp2 的效果能不能由"在动作上推同样大小的一把"得到？

**问题 2（P5 留出检验）**：不改任何设置（第 12–14 层、图像 token、λ = 2），把同一个修复用到没参与选窗口的任务对和套件上：
- 能不能救回切换失败？
- 会不会损坏原本能成功的切换和从头给 B 的运行？
- 和三种不需要定位的修复比，谁更好？

**预先写下的预测**：
- 闭环里 amp2 把"继续做 A"变成"去做 B"，两边都没做成的情况没变（14 对 14）。所以修复应当只救 **commits 型**失败格（native 失败时多半把 A 做完），救不了 **derails 型**（两边都没做成）。
- LIBERO-10 在 .25 / .5 主要是 derails，那里应当没有效果。若有效果，"只救继续做 A"这一描述就要改。

## 2. 臂

所有臂都用 `serve_steer.py` 里同一套程序（`patching.Patcher.steer`）。同一状态的各臂，每次请求的噪声相同（RNG 在运行开始时重置到前缀种子）。

| 臂 | 做法 | 用途 |
|---|---|---|
| native | 什么都不动（λ = 1） | 基线 |
| amp2 | 第 12–14 层图像 token 的 K/V 沿 B − A 放大到 2 倍（同闭环） | 被检验的修复 |
| rand2 | 同样大小的 K/V 改动，方向随机（同闭环，同一串方向种子） | 表示空间里的随机对照 |
| **actrand** | 每次请求先算 amp2 和 native 的动作块，输出 native 加一把随机推动；推动在每一行、每个动作分组（平移 3 维、旋转 3 维、夹爪 1 维）上的大小等于 amp2 这一行这一组的改动，方向每组一个、整局固定 | **动作上匹配的随机对照**（问题 1） |
| **actdiff** | 同样的噪声下分别用 B、A 算 native 动作块，输出 a_B + 1·(a_B − a_A) | 不碰模型内部的修复（类似在输出上做 classifier-free guidance） |
| **rephrase** | 指令换成 "do not {A}. {B} instead"，什么都不动 | 只改提示的修复 |
| **ampall** | 和 amp2 一样，但作用在全部 18 层的图像 token 上 | 不定位的 steering（方案里的"普通 steering"） |

- **actrand 的细节**：
  - 推动方向由 `repair.push_seed(SW id)` 定，与 rand2 的方向无关。夹爪是一维的，"方向"就是一个固定的正负号。
  - 方向整局固定，所以它是"朝一个方向持续推"，不是逐步抖动。这比逐步换方向更接近"推一把就能把机器人从 A 的惯性里推出来"这一对立解释。
  - 大小在动作块的每一行上都匹配，包括不执行的后 5 行，所以不依赖执行几步。
  - amp2 的改动是在 actrand 自己的轨迹上算的，即"在这个状态上 amp2 会改多少"。
- **actdiff 的细节**：在输出的动作块上外推，不是在每个去噪步的速度场上外推；后者没试。
- **剂量**：amp2、rand2、ampall、actdiff 都用 λ = 2，预先固定，不调。actrand 跟着 amp2。
- **触发**：同闭环，只在"指令被换"之后的运行里干预，旧指令 A 已知；起点格（f = 0）沿用闭环的做法，用 A 作旧指令。

## 5. 读法

第 5 节状态：已冻结（2026-11-04，提交前；冻结后读法和门槛不改）。

**只用正式批次的初始布置 2–19。** smoke 的初始布置 0、1 只作描述，不进读数。

**统计**：同闭环。状态按阶段 1 的 SW 分支配对，比较同一状态在两个臂下的 b_done；差的均值和 95% 区间用 bootstrap 求，按格分层、格内重抽状态，2000 次，种子 0（`closed_loop.paired`）。

**C1 工具核对**（smoke 和正式都要过），`tool_ok` 需要以下全部成立：
1. 每次运行都完成，哈希核对通过，结果能由轨迹重算出来；服务端日志与客户端逐请求一致；
2. 切换步的物理哈希与阶段 1 同一 SW 分支相同；
3. 请求 1 上，干预程序在 λ = 1 时与 `Policy.infer` 的 L∞ 差：中位 ≤ 0.01，最大 ≤ 0.05；
4. native、rephrase、actdiff 臂没有任何 K/V 改动；native、rephrase 臂请求 1 的动作与 λ = 1 相同；
5. amp2、rand2、ampall、actrand 臂每次请求的 K/V 改动 ÷ ((λ − 1)·‖B − A‖) 与 1 的差 ≤ 0.001；
6. actrand 每次请求、每行每组的推动大小与 amp2 改动之差（绝对值）≤ 1e-5；
7. 除 native、rephrase 外，每个臂在请求 1 的动作块都与 λ = 1 时不同；
8. rephrase 臂实际用的指令是 "do not {A}. {B} instead"，其余臂是 B。

只报告、不作门槛：native 与阶段 1 一致的比例；第一个策略输入哈希与阶段 1 相同的比例；每臂的耗时、请求 1 动作变化的中位、actrand 推动大小和 actdiff 的 ‖a_B − a_A‖ 的中位；动作越界次数。

**R6 动作匹配对照**（闭环失败格，90 个状态）：
- `direction_specific`：amp2 − actrand 区间下界 > 0；
- `push_suffices`：否则，且 actrand − native 区间下界 > 0；
- `unclear`：其余情况。

**R7 留出恢复**（闭环 R4 的规则：增益 = amp2 − native，特异性 = amp2 − rand2），commits 型（52 个状态）和 derails 型（86 个状态）分别读：
- `restores_switch`：增益 ≥ 0.15，增益区间下界 > 0，特异性区间下界 > 0；
- `weakly_restores`：增益和特异性的区间下界都 > 0，但增益 < 0.15；
- `nonspecific`：增益区间下界 > 0，特异性区间下界 ≤ 0；
- `harms`：增益区间上界 < 0；
- `no_restore`：其余情况。
预测：commits 型 `restores_switch`，derails 型 `no_restore`。

**R8 留出选择性**（闭环 R5 的规则，留出成功格加起点格，318 个状态），改变 = amp2 − native：
- `selective`：区间下界 ≥ −0.10；
- `damages`：区间上界 < 0 且改变 ≤ −0.10；
- `unclear`：其余情况。

**R9 不需要定位的修复**（commits 型失败格合并：闭环失败格 90 个 + 留出 commits 52 个，共 142 个状态），对 actdiff、rephrase、ampall 各读一次：
- `amp_better`：amp2 − X 区间下界 > 0；
- `x_comparable`：否则，且 X − native 区间下界 > 0、均值 ≥ 0.15；
- `unclear`：其余情况。

**只报告、不作读数**：
- amp2 − native 在闭环失败格上（重复闭环结果）；
- R6 在留出 commits 格上；
- R7 在全部留出失败格上合并；amp2 − actrand 在留出失败格上；
- 留出成功格、起点格、中间格分别的 amp2 − native；
- R9 在闭环失败格、留出 commits 格上分别；
- 每格每臂的切换数、失败时 A 完成数、换成功用的步数、请求 1 动作变化的中位。

**解读规则**（写在运行前）：
- **R6 `direction_specific`**：在动作上推同样大小、方向随机且整局一致的一把，不能替代 amp2；"推一把也行"在这个意义上被排除，第 12–14 层图像路的因果说法成立。
  **`push_suffices`**：不能排除；图像路的说法降为"一种能让切换发生的扰动"，不再说是图像路特有的。
- **R7 commits `restores_switch` 且 R8 `selective`**：修复迁移到没参与选窗口的任务对和套件，P5 在留出上通过。
  **commits `no_restore`**：不迁移；效果限于试点任务对或 LIBERO-Goal。
  **derails `restores_switch`**："只救继续做 A"的描述不对，要改。
  **R8 `damages`**：修复在留出上会损坏原本能做的运行，不能作为通用修复。
- **R9 某个 X 读成 `x_comparable`**：这种不需要定位的修复也行，修复本身不需要机制定位（actdiff 的话，连模型内部都不需要）；R6 和闭环的因果结论不受影响。
  **`amp_better`**：在同样预先固定的剂量下，定位的干预比 X 好。
- R9 只比修复效果；三种替代修复在成功格和起点格上的选择性没测。

## 7. 风险

- **LIBERO-10 的局长**：失败局 520 步，占正式算力的一半左右。
- **留出的 commits 格有两个在 .75**：闭环里 2→9 的 .75 只救回 4/18（A 已做得太远）。所以 commits 型读成 `no_restore` 也可能只是"太晚"，报告时按格分开看。
- **替代修复只试了一个剂量**：ampall 作用在 18 层上，同样 λ = 2 的总改动比 amp2 大得多，可能过量；actdiff 和 rephrase 也没调。R9 只说明"同样预先固定的剂量下"谁更好。
- **actrand 只是一种动作对照**：方向整局固定、大小逐行逐组匹配。逐步换方向的抖动、朝 B 目标的"有方向"推动都没试。
- **闭环数值噪声**：native 与阶段 1 约 93% 一致；对照一律用同批次的 native。
