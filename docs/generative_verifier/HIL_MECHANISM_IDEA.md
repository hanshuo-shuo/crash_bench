## 1. 研究问题

π0.5 在 LIBERO-Goal 上从头给熟悉指令 B 时能完成，任务中途换成 B 却可能失败。我们要回答四个问题：

1. 在换不过去的状态里，B 的信息断在哪一段计算上？候选有三处：VLM 一侧没有编码；经过动作专家读前缀的接口时没传过去；动作专家收到了，却没有变成动作。
2. 这三段在"换得过去"和"换不过去"的状态之间有什么差别？
3. 能否找到可被独立例子推翻的功能解释？
4. 能否在不借助额外特权信息的前提下，有选择地改变这一环节？

STOP、RETURN、DETOUR 需要的能力和熟悉指令切换不同，这次不作为修复目标。它们以后可以作为边界实验另议，不预设和切换共用同一机制。

论文要靠四类证据才站得住：
- 可复现的行为差异；
- 在内部计算上的因果定位；
- 能被独立例子推翻的解释；
- 保留正常能力的选择性改变。

只有激活图，只能说相关；所有任务都不动了，只能说运动被压制。

## 4. 模型事实（读 openpi 代码得到）

运行用的 openpi 是 `third_party/vlsa-aegis/openpi`，它的模型代码和 `/projects/p33100/siosio/third_party/openpi` 相同。

- **输入**：`pi05_libero` 不输入本体状态（`discrete_state_input=False`，π0.5 的动作专家也没有 state token）。每个动作块只由主视角、腕部两张图和指令决定，没有历史；第三个相机槽被掩掉。
- **前缀**：每张图 256 个 token，接着是文字 token（BOS + 指令 + 换行，上限 200）。图像和文字之间是**全双向**注意力。
- **动作专家**：18 层，每层读前缀的 K/V，时间步经 adaRMS 进入，10 步 Euler 积分。动作块 H = 10，执行前 5 步。
- **神经元**：GeGLU 隐藏单元 `gelu(gate)·up`，VLM 每层 16,384 个，动作专家每层 4,096 个。
- **指令长度**：三对指令的 token 数分别是 8/8、6/8、11/9。
- **存档输入**：阶段 1 每个分支都存了切换那一刻的策略输入 `first_policy_input.npz`，还有那一刻的原生动作块和输入哈希（`POLICY.jsonl` 第 1 次请求）。A 的对照在 f = 0 是前缀运行本身，其余时点是 C0 分支，种子与 SW 分支相同。
- **渲染噪声**：孪生的物理哈希相同，但主视角图像在少数像素上可能差 1 个灰度级（EGL 渲染）；前 120 对里有 62 对如此。所以 A、B 两条指令都喂 SW 分支存的那份输入。

## 5. 三种解释与对应测量

| 解释 | 预测 | 测量 |
|---|---|---|
| 1. 语义：中途 VLM 一侧没把 B 编进动作专家要读的 K/V | 前缀里 B 与 A 的差（gaps）比 t = 0 小；从 B 替换的效果也小 | `gaps`：每层的值向量差，图像 token 和文字 token 分开 |
| 2. 传递 / 读出：B 的信息在前缀里，但动作专家没用上 | gaps 不小，A/B 动作差或接口 E 却小 | 接口 patching 的 E，按层窗口和 token 分组 |
| 3. 物理可达：信息到了，也变成了朝 B 的动作，闭环仍失败 | E 正常、动作朝 B 改变，但完成不了 | 闭环结果（阶段 1 已有）、P2b/P3 的闭环 patching |

三种解释可能同时存在，按任务对、按时点分别读，不预设一个"门"。

## 6. 研究单位与指标

- **状态**：P0 的 240 个（3 对 × 4 个时点 × 20 个初始布置），不按结果挑。smoke 用初始布置 0、1，共 24 个。
- **每个状态的输入**：SW 分支存的输入；A = 原任务指令（base），B = 新指令（donor）。4 个噪声种子：分支自己的种子，加 1、2、3。同一种子下 A、B 和替换后的运行共用噪声。种子 0 的噪声和原运行第一次请求完全相同，所以能和存档原生动作块逐位核对。
- **path**：动作块 10 步平移的累积和（3 × 10）。用它代替 Goodfire 由正运动学还原的末端轨迹。
- **E** = ⟨path(替换) − path(A), path(B) − path(A)⟩ / ‖path(B) − path(A)‖²。0 表示还是 A，1 表示完全变成 B 引起的变化。
- **噪声底**：同一句话、不同种子的 path 距离中位数。
- **E 只在部分种子上读**：|path(B) − path(A)| 达到噪声底 3 倍的种子；一个状态至少有 2 个种子可读才计入。
- **统计**：每格 = 一个任务对、一个时点。每个初始布置一个状态，报中位数和 bootstrap 95% 区间，按初始布置重抽。
- **干预**：
  - **interface**：选定的动作专家层读 B 的前缀 K/V。层可以是单层，也可以是连续 3 层的窗口；token 分组可以是全部、图像或文字。不等长时，被替换的组按 B 的掩码读，B 的 K 按长度差重新做 RoPE 旋转，相对位置因此和 B 运行时一致。
  - **backbone**：把某一层 VLM 的输入残差在图像 token 上换成 B 的；只有两句等长（1→8）时才换文字 token。
  - **gaps**：只读，不干预。
- **不变量**：同一请求里所有运行走同一个程序，所以空替换逐位等于 A；等长时全替换逐位等于 B，不等长时只差 bf16 旋转的舍入。

第 7 节状态：已冻结（2026-11-04，P1 smoke 之后、正式批次之前；冻结后读法和门槛不改）。

- **R1（P2）**：在 smoke 之前就写好了，所有初始布置都参与读数。
- **R2、R3（P3）**：看过 smoke（第 11 节）之后才写，所以读数**排除 smoke 用过的初始布置 0、1**，只用 2–19。每格 18 个状态，是 smoke 之外的独立样本。

**P0：选状态（已完成，只读）**
- `experiments/mechanism/selection.py`，读阶段 1 分支存档，得到 240 个状态，各格计数见第 3 节。
- 核对种子、切换步、A/B 的 RNG 起点一致，阶段 1 存档哈希完整。

**P1：工具核对（GPU smoke，24 个状态）**

`tool_ok` 需要以下四条全部成立：
1. 重建的 B 输入哈希等于原运行记录的输入哈希，所有状态都要成立；
2. 空替换与 A 的最大差 = 0；
3. 每个可读种子上，全接口替换的 E 在 1 ± 0.02 之内；
4. 本作业里，替换程序的 A 和 openpi `Policy.infer`（同种子）的 path 差：中位 ≤ 0.1 噪声底，最大 ≤ 0.5 噪声底。

只报告、不作门槛的项：
- 本作业的原生输出与存档的哈希一致数和 L∞（反映跨作业的数值噪声）；
- A 孪生输入是否逐位相同；
- 可读状态的比例；
- 逐层前缀与原生前缀的差。

`tool_failed` 就停下修代码、重跑 smoke，不进入正式批次。

**P2：t = 0 正对照（正式批次的 f = 0 部分；smoke 先看一眼）**
- **读法**：对每个任务对，取连续 3 层、全 token 窗口里每格 E 中位数最大的那个，由最差的那一对决定：
  - ≥ 0.7：`interface_found`（门槛沿用 Goodfire 在 DROID 上的数）；
  - 0.4–0.7：`interface_partial`；
  - < 0.4：`interface_absent`，停下检查方法和研究单位，不往中途扩。
- **描述性**：最佳窗口上图像组和文字组各占多少；单层曲线；backbone 图像组的逐层曲线。
- **P2b 闭环确认**（要新写运行器，并单独点头）：f = 0，指令保持 A，每次推理在同一画面上算一次 B，只替换最佳窗口，看 B 的完成率。预定读法：达到上限的 0.7 倍为 `closed_loop_confirms`。

**P3：中途（正式批次）**

**两个量**：
- **带内图像 gap**：每个状态在第 12–17 层上，图像 token 的值向量 B 对 A 的相对差取平均。它不依赖 E，所以所有状态都能算。
- **配对比值 γ**：同一个初始布置，时点 f 的带内图像 gap 除以 f = 0 的。

**格的划分**：按阶段 1 的切换率相对 f = 0 上限分。
- **成功格**：≥ 上限的 0.9，即 1→8 的 .25、.5、.75；
- **失败格**：≤ 上限的 0.5，即 7→8 的 .5、.75，以及 2→9 的 .25、.5、.75；
- 7→8 在 .25 是上限的 0.75，两头都不算，只作描述。

**R2：任务信息在图像 token 上的印记，是否在切换失败的地方变淡**（`metrics.route_reading`）

每格取 γ 的中位数，并按初始布置 bootstrap 出 95% 区间。
- `image_route_fades`：每个失败格的中位 ≤ 0.8 且区间上界 < 1，同时每个成功格的区间下界 ≥ 0.9；
- `image_route_kept`：每个失败格的区间下界 ≥ 0.9；
- `mixed`：其余情况。

预测是 `image_route_fades`。

**R3：同一格内，γ 越大是否越容易换成功**（`metrics.switch_auc`）

- **入选格**：同时有 ≥ 5 次成功和 ≥ 5 次失败的格。按阶段 1 结果，预计是 7→8 的 .25、.75 和 2→9 的 .5。
- **统计量**：按格分层的 AUROC，权重为成功数 × 失败数；bootstrap 时在格内重抽状态。
- **读法**：
  - `gap_predicts_switch`：AUROC ≥ 0.7 且区间下界 > 0.5；
  - `gap_weakly_predicts`：区间下界 > 0.5，但 AUROC < 0.7；
  - `gap_does_not_predict`：其余情况；
  - 没有入选格时为 `insufficient`。

**描述性（不作门槛）**：
- 每格的可读比例；
- P2 最佳窗口上的 E，按全部、图像、文字三组分开；
- 文字 gap 的 γ；
- backbone 曲线。

**解读规则**（写在运行前，用来把结果对应到第 5 节的三种解释）：
- R2 读成 `image_route_fades`，而文字 gap 不变：B 的信息在文字 token 上仍然存在，但没有进入动作专家主要读取的图像 token。这对应解释 1 的一种具体形式。如果某一对的总 E 靠文字 token 维持（smoke 里的 2→9），而切换仍然失败，就要另查解释 3，即 B 自己的输出在这个状态做不成 B。
- R2 读成 `image_route_kept`：图像这条路没有变淡，失败要到动作专家内部（解释 2）或物理可达性（解释 3）里去找。
- **可读比例不等于成败**：smoke 里 1→8 在 f = 0 和 .25 时 A/B 动作差小于 3 倍噪声，切换却全部成功。这是因为两个任务此刻都要先去抓碗，第一个动作块本来就该相同。所以"E 读不出"不能当作"B 没起作用"。

**还没实现的 P3 工具**：
  - 把 t = 0 时 B 的文字 K/V 移植到中途状态（同一句话，位置对齐）；
  - 把 B − A 的差在最佳窗口上按倍数放大；
  - 失败状态上的闭环 patching。

**P4：神经元调查（P3 找到稳定的因果位置之后）**
- **筛选**：在定位到的层里看 GeGLU 神经元。先用 attribution 粗筛，再用真实的单神经元替换复核，因为 π0.5 上归因不可靠。每组对比取 top 10，作为首轮预算。
- **档案**：在状态 × {原句、空指令、随机串、STOP、RETURN} 上记录最强的正、负激活。
- **解释与盲测**：写解释；独立测试者只看解释，对留出的状态和句子（含相近反例）先写预测再测。
- **因果检验**：失活、钳制、放大；配同层随机、同幅度的对照。
- 通过标准在 P4 之前写定。如果找不到少量能单独解释的神经元，结论就停在电路层面，不硬说 Goodfire 的 clean 假说在 π0.5 上成立。

**P5：选择性修复（单独批准）**
- **触发**：只在"指令被换"这一事件后干预，不用 re-entry 位姿。
- **对照**：改写提示、普通 steering、随机同幅度干预。
- **选择性**：不换指令时，同样的干预下 A 必须照常完成；原本换得过去的切换不能受损。
- 和 Causeway 的数字只作定性比较，它没有公开代码。

## 10. 风险

- **可读状态可能很少**：中途很多状态的 A/B 动作差可能不到噪声的 3 倍（2→9 一直小），E 读不出来。这本身也是结果，但会限制 P3 能讲的东西。
- **舍入误差**：不等长时的 RoPE 重旋转在 bf16 下有舍入，P1 的全替换容差 0.02 就是为此留的。
- **范围窄**：一个检查点、只有仿真、三对任务、每格 20 个状态。这是 pilot，不能当泛化证据。
- **指标不全**：E 只看平移，转动和夹爪另报。
- **神经元未必干净**：原生神经元可能不像 Goodfire 说的那样干净，结论可能停在电路层面。
