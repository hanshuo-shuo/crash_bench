## 一句话

- **预注册读法 `both_shortcut`**：A 0.501、B 0.503，都 ≤ 0.60；训练拟合 A 0.723 ≥ 0.70。两组在反事实孪生上都停在随机水平，写事实没有让 B 去看图。
- **更准确地说，两组都停在了"规则 × 进度"的先验上，连训练集都没学到先验以上**：训练拟合（0.723 / 0.715）低于查表上限 0.760，B 在训练图上的两个事实（0.66 / 0.69）也和查表（0.658 / 0.691）差不多。这不是"学会了捷径、没学会看图"，而是一个 epoch 后什么图像关系都还没学会。
- **B 的问题在看图，不在组合**：B 写出的两个事实都对时，判定 100% 对；判定和它自己写的事实 100% 一致。但验证上两侧事实同时对的只有 44%：篮子侧几乎总写 "no"（1.2% 写 yes，真值 28.7%），物体侧只比查表高 8 个百分点。
- **自然诊断上两组都有 0.89**，高于查表的 0.747：自然布局只有一种，模型记住了它。"在自然数据上看起来很好、在反事实孪生上是随机水平"，这正是 V5 想暴露的现象，但现在 A 和 B 都是这样。
- **零样本也读不出这两个事实**：3B 基座和本地 Qwen3-VL-32B 两种提示都在随机水平（0.487 / 0.500 和 0.500 / 0.477），而且都是常数回答：3B 两侧全写 no，32B 99% / 87% 写 yes。S1 盲看在同样两张斜视图上三项都是 40/40，所以信息在图里，是这两个开源模型读不出来。
- **下一步需要讨论**（读法 `both_shortcut` 规定的）。建议先做一次便宜的拟合诊断，分清"3B 在 448 像素下看不出这个关系"和"训练不够"，再决定换事实写法还是加训练。

### R7（解释用）：预测是不是跟着查表走

- 验证集上查表本身 87% 预测"不可行"。A 有 96% 判"不可行"，所以和查表 0.848 一致，但这主要来自两者都偏向"不可行"：
  - 查表说"可行"的行里，A 也只有 5% 判"可行"；A 与查表的 kappa 0.02，与真值 0.003。
  - 下面的事后分析换了一种看法：在同一"规则 × 进度"组里，A 96% 的行给同一个答案，而真值在组内各半。A 没有用到布局。

## 事后分析（不进入读法）

脚本和结果存在运行目录的 `posthoc/`（`posthoc.py`、`POSTHOC_DIAGNOSTICS.json`），只读验证记录和训练行。

| 指标 | 物体侧 | 篮子侧 |
|---|---:|---:|
| B 写 yes 的比例（真值） | 0.864（0.653） | 0.012（0.287） |
| B 准确率 − 查表准确率 | +0.084 [0.053, 0.115] | +0.041 [0.029, 0.056] |
| 与真值的 kappa | 0.13 | 0.03 |
| 同一"规则 × 进度"组内答案相同的比例（真值） | 0.877（0.670） | 0.988（0.715） |

- **篮子侧塌成常数 "no"**：+0.041 来自"全写 no"本身就能拿到 0.713，不是看图。
- **物体侧有一点信号**：比查表高 8 个百分点，区间不含 0；同一张图换一条规则时，真值物体侧有 34% 会变，B 只变了 14%。
- **训练损失**：B 的判定 token 损失在第 200 次更新后约为 0（判定完全由事实决定）；事实值 token 的平均损失停在约 0.12，折算到两个 yes/no 位置约等于先验的熵。A 的判定损失停在约 0.5，也约等于 76% 先验的熵。

## 对故事意味着什么

- **预期没有出现**：预期是 A 学捷径、B 因为要写事实而去看图。实际是两组都停在先验上，写事实没有带来看图。
- **V4 的结论没有被推翻，但也没有推广到 V5**：
  - V4 里 B 的事实是"白框物体在不在橙色框里"，框是画上去的、颜色鲜明；
  - V5 的事实是"布丁在两件真实杂货连线的哪一侧"，要在两张斜视图里估计一条看不见的线。后者的感知难度高得多。
- **B 的组合已经完全学会**，所以瓶颈很清楚：是感知"机器人侧"这个关系，不是从事实推出判定。
- **开源 VLM 零样本也读不出这个关系**：32B 和 3B 都给常数回答，方向还相反。Claude 盲看能读出，说明信息在图里，但对 Qwen 系列不是一眼可见的。
- **还不能区分两种原因**：
  1. 3B 模型在 448 像素的两张斜视图上读不出这个关系（感知上限）；
  2. 一个 epoch、1,792 行的训练不够（训练拟合还没超过先验，指向这一条）。
