# 单通路对照报告：两个因子各自学得会，组合学不会；复述颜色后就学得会

2026-10-18。协议：[CONTROLS_PROTOCOL.md](CONTROLS_PROTOCOL.md)（规则在作业前冻结，commit `0356185`）。

> **2026-10-19 更正**（见 [LADDER_REPORT.md](LADDER_REPORT.md)）：本报告"先写颜色就够了""B 的可训练性优势不需要两个包含关系"的推论不成立。
> - 判定前只加 4 个固定 token（AF）也能拟合这 16 行，所以 A+P 的拟合靠的是多出来的输出位置，不是颜色。
> - 在 512 行上，AF 和 A+P 在训练集和验证集上都停在 50%；B 是 84.5%（AP − B = −34.7 个百分点，区间 [−39.7, −30.1]）。
> - 下面的数字和预注册读法本身没有错。错在把 16 行上的拟合当成了"学会规则"：16 行测的更像是"能不能记住 16 个例子"。

## 结论速览

- **按预注册的读法**：
  - t / s 记为 `composition_bottleneck`：两个单一模态的标签都学会了，而第 1 步里它们的 XOR（原判定）没学会；
  - A+P 记为 `restatement_restores_fit`：先把受保护颜色写出来，同一个 XOR 判定就学会了。
- 9 次运行全部是"能拟合"：第 160 次更新时 16/16，最后一个 epoch 的判定损失约为 0。
- **能说的**：在当前设置下，direct 路径学不会的是把两个通路组合起来；输出里先复述颜色，就足以恢复拟合。
  所以在这 16 行上，B 的可训练性优势并不需要两个包含关系。
- **不能说的**：
  - 这个作业分不开"复述了颜色"和"判定前多了几个输出 token"这两个因素；
  - 16 行属于记忆的范围，A+P 能不能像 B 一样泛化，还不知道；
  - 梯度机制仍未测量。

## 3. 解读与限制

- **组合是瓶颈**：两个因子各自都学得会，图像那一路甚至最快。A 失败的原因不在任何单一通路，而在把两者组合起来。
- **复述颜色就够了**：A+P 的判定仍然是 s XOR t，只是 t 已经作为一个输出 token 写在判定前面。
  在这 16 行上，这样已经能拟合，不需要 B 的两个包含关系。
- **描述性的观察（没有测量机制）**：
  - 只看文字的 t 反而比只看图像的 s 慢，提示"把约束文字深处的颜色词映射到判定位置"本身就慢；
  - A+P 让模型先把颜色抄进输出。抄写更接近预训练里已有的能力，20–40 次更新就学会了，判定随后也学会了。
- **还不能区分的**：
  - "复述了颜色"与"判定前多了几个输出 token"。需要一个只加 token、不带颜色信息的对照才能分开；
  - 拟合与泛化。16 行能拟合，不说明在没见过的源上也能判对。
- **作用范围**：Qwen2.5-VL-3B、语言侧 LoRA r16、学习率 1e-4、160 次更新、这 16 行。

## 4. 对此前结论的影响

- **第 1 步的结论加强了**："中间监督改善了这种图文联合判断在当前设置下的可训练性"。
  现在可以更具体地说：起作用的可能只是在判定前写出受保护颜色，而不一定是两个包含关系。
- **B − A = +29.7 个百分点（锁定测试集）仍然成立**，但它的来源要重新拆分：
  - 是"写出颜色或改变输出结构"；
  - 还是"预测两个包含关系"。
  这要靠在 512 行上比较 A+P 与 B 的验证集表现来回答。

## 5. 建议的下一步（需要用户批准新的训练）

1. **加一个 token 数对照**（约 20 分钟，16 行，3 个 seed）：把 `Protected: <颜色>` 换成长度相同、不随输入变化的固定文字，再写判定。
   - 学得会：多出来的输出 token 本身就够；
   - 学不会：起作用的是写出的颜色。
2. **第 2 步的简洁对照中加入 A+P**：在 512 行上比较 A、A+P、R（两个关系 + 程序规则）和 B，3 个 seed，只用验证集，训练中只做 greedy 验证。
   - A+P ≈ B：B 的优势主要来自写出颜色或输出结构；
   - A+P 明显低于 B：两个包含关系对泛化有额外作用。
   - 预计约 4–5 A100 小时，最多同时用两张卡。
3. **梯度测量继续后置**。现在有了更直接的对照路线，它不再是解释结果的前提。
