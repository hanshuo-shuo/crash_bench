## 1. 要回答的问题

P 的 94% 来自"训练过的 VLM 写出四个点，固定代码判定"。审稿人最先会问：**不训练行不行？**
AEGIS 自己就带一个现成的开放词表检测器（GroundingDINO），用它找到这四个物体，再跑同一段程序，能不能也判对？

- 如果能：训练定位在这个任务上不是必需的，故事要写成"模块化定位加程序判定"，AEGIS 闸门可以直接用它自带的检测器。
- 如果不能：P 的位置监督是必要的，闸门的感知用 P。
- 对照：S4 的 R6 里，Qwen3-VL-32B 零样本指点再跑程序是 0.451（选模子集 384 行），但那是让 VLM 指点，不是专门的检测器。

- **授权**：用户 2026-10-26 "先做1"。对应的建议是：GroundingDINO 加程序的基线，只看验证集，只做推理，约 1 GPU 小时，不调 API，不改控制器。
- **不做的事**：
  - 不读测试集（`test`、`test_natural` 已在 10-26 用过一次）；
  - 不训练、不微调检测器；
  - 不调 API，不重新渲染；
  - 不在验证集上调任何东西：查询词、选框规则、框到点的换算都在下面写定，唯一要定的两个比例只用训练集定。

## 2. 设计

### 检测器

- **GroundingDINO SwinT-OGC**，就是 AEGIS 复现时用的那份权重（`groundingdino_swint_ogc.pth`，sha256 `3b3ca256…`，见 `staging.json`）。
- 在 AEGIS 的环境里跑：容器 `aegis-py38.sif`、环境 `envs/aegis_sim`（groundingdino-py 0.4.0，torch 1.11），BERT 用复现时核对过的离线快照。
- 用 GroundingDINO 自带的 `load_image`（短边缩放到 800）和 `predict`，与 AEGIS 的 `get_point_cloud` 相同。

### 输入和查询

- **图**：第 1 张图（`overview_a`，448×448），就是 P 写坐标的那张。只用 RGB，不用深度，P 也没有深度。
- **查询**：每张图对布丁、篮子、这张图的规则里出现的每个锚点各查一次。
  - 查询词就是规则文字里的物体名，去掉 "the"：`chocolate pudding`、`basket`、`salad dressing bottle` 等（`v5_pos_contract.entity_phrase`）。
  - 只用这一种写法，不试别的。

### 选框

- **主规则**：900 个候选框里分数最高的一个。分数是框对查询词各 token 的 sigmoid 的最大值，与 `predict` 相同。这样每次查询都有一个框，不会缺点。
- **AEGIS 原规则（诊断）**：分数超过 0.35 的框里，按候选顺序取第一个，这就是 AEGIS 的 `get_point_cloud` 的取法。没有超过 0.35 的就记为缺点，这一行算错。

### 框换成桌面点

- P 写的是物体正下方的桌面点（S4 协议第 2 节）。检测器只给框，所以按框换算：
  - x = 框的中心；
  - y = 框的上沿 + f × 框高。
- **两个比例**：
  - 静止物体（两个锚点、篮子）用 f_s，候选 {0.5, 0.6, 0.7, 0.8, 0.9, 1.0}；
  - 布丁用 f_t，候选 {0.5, 0.75, 1.0, 1.25, 1.5, 2.0, 2.5, 3.0}。布丁常被夹在半空，它的桌面点在框的下方，所以允许超过框底。
- **只用训练集定比例**：在训练集 1,792 行上，从 48 种组合里选程序判定准确率最高的一组；平分时选训练图上所有桌面点中位误差更小的；再平分按候选顺序取较小的比例。验证集不参与。
- **参照规则（诊断，不校准）**：框中心（0.5, 0.5）、框底（1.0, 1.0）。

### 程序

- S4 的 `program_separated`，一字不改：布丁点和篮子点严格落在两个锚点所连直线的两侧，算隔开，判 0，否则判 1。
- 两个锚点的点重合，或者有缺点，按判错。
- 真值点用 S4 的 `POINTS.json`（preflight 重算并要求逐张相同）。

### 已知的劣势（如实写进报告）

- 布丁被抬起时，2D 框推不出它正下方的桌面点；P 是从位置监督里学到这一点的。所以 D8 按进度段分层。
- 检测器每次只看一张图，P 输入两张图（但只写第 1 张图上的坐标）。

## 3. 读数（只看验证）

| 读数 | 定义 |
|---|---|
| D1 | 完整验证集（1,538 行）上的程序判定准确率（主读数），图像 bootstrap 95% 区间；与 P 的配对差 P − D（P 取 3 个 seed 按行平均，0.940）及其区间；A 的 3 个 seed 平均（0.500）只作参照 |
| D2 | 孪生图全对率 |
| D3 | 布丁、篮子、锚点（锚点再按物体名）分别统计：<br>- 命中率：框中心落在物体投影包围框内，框放宽 4 像素（同 S4 R6）；<br>- 桌面点误差：中位数、15 像素内比例、30 像素内比例；<br>- 所选框的分数 |
| D4 | 验证自然（79 行）上的准确率 |
| D5 | AEGIS 原规则：缺点率、准确率 |
| D6 | 参照规则（框中心、框底）的验证准确率；校准表（训练集上 48 组的准确率） |
| D7 | 选模子集（384 行）上的准确率，对照 S4 R6 的零样本 32B 0.451、3B 0.398 |
| D8 | 判错的行拆成两类：有物体没命中（找错或没找到），四个都命中但还是判错（点的位置偏）；按进度段和按源分层 |
| 训练集 | 选定比例下训练集的准确率，只作参考（比例是在这上面选的） |

- **不确定性**：以图像为单位做 bootstrap，1,000 次，seed 1014；按源的区间只作参考（验证集只有 4 条源）。
- 检测器是确定性的，只有一次运行；P 的 3 个 seed 是固定的，区间只反映换一批图像的不确定性。

## 4. 读法（事先写定）

设 D 为 D1 的准确率，区间指 P − D 的图像 bootstrap 95% 区间。

| 读法 | 条件 | 含义 |
|---|---|---|
| `detector_close` | D ≥ 0.85 | 不训练、只在训练集上定了两个比例的现成检测器加程序，已接近 P（差不到 10 个点）。训练定位在这个任务上增益有限；闸门可以先用 AEGIS 自带的检测器；故事要写成"模块化定位加程序判定"，而不是"训练 VLM" |
| `training_needed` | D ≤ 0.75，且区间下限 ≥ 0.10 | AEGIS 用的现成检测器给不出够准的位置，P 的位置监督是必要的；闸门的感知用 P |
| `between` | 其余情况 | 报告后讨论 |

## 5. 运行与资源

- **启动**：`python -m verifier_training.launch_v5 det --s3 <S3> --s4 <S4> --seeds <加 seed>`。
  - 新建 `verifier_training/runs/<UTC>_v5-det_<commit>/` 并归档源码；
  - `RECEIPT.json` 记下要读的旧文件、检测器权重、配置、容器和环境的哈希；旧运行目录只读。
- **作业**（任何时候最多 1 张 GPU）：
  1. CPU preflight（openpi 环境）：跑单元测试；重算真值点并要求与 S4 的 `POINTS.json` 相同；核对每张图的哈希；写查询表 `QUERIES.json`。
  2. GPU detect（1 张 A100，AEGIS 容器，preflight 成功后才开始）：逐个查询跑检测，写原始框和分数。结束时把前 16 次查询重跑一遍，最高分框的编号和坐标必须完全相同，否则停。
  3. CPU report（openpi 环境）：定比例、算全部读数，写 `DET_READING.json`。
- **预计用量**：约 7,190 次查询（训练 4,664、验证 2,319、验证自然 207）；GPU 不到 1 小时；两个 CPU 作业各约 15 分钟。不调 API。
