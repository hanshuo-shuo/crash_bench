## 2. 和整体研究方向的关系

`docs/new_report.md`（在 `codex/paired-repeats` 分支上）里的 Direction 1 要区分三种情况：

- (a) 任务一开始就不可行；
- (b) 还能恢复，但当前策略不会；
- (c) 执行过程中逐渐失去恢复的机会。

这个 verifier 针对的是 (a)，而且是在声明的约束合同下、有证明的版本：
- 负例有封闭分隔证书；
- 正例有真实的安全轨迹；
- 策略失败一律记为 UNKNOWN，不当作不可行。

## 3. 请 Astra 重点核查

按"如果错了影响最大"排序：

1. **A 的常数预测是不是 bug？**
   - **现象**：3 个 seed 的 verdict 损失都降到 0.70 左右（ln 2），三个检查点都给出常数预测。
   - **该看的代码**：
     - `verifier_training/fd1000_run.py` 的 `encode`：direct 目标、标签掩码、单 token 判定检查；
     - `train`：样本顺序、损失、选模；
     - `fd1000_contract.schedules`。
   - **已有的反证**：
     - preflight 逐行核对过 A/B 的推理输入完全相同、判定是单个 token；
     - 梯度探针显示 verdict 损失能把非零梯度传到 LoRA；
     - B 走的是同一条代码路径，只是目标不同。
   - **还没做的**：用已保存的 A adapter 在训练集上评估。如果连训练集都拟合不了，就是优化问题，而不是过拟合。
2. **C 的设计是否公平**：C 每个 epoch 只有一半样本是事实目标，所以它见到的事实监督只有 B 的一半。
   C 写事实读法低于 B，可能只是因为这个。
3. **数据和标签**：
   - 结构化事实在 `verifier_training/v4_export.py` 里由构造元数据推出，并断言与 `LAYOUT.json` 的几何一致；
   - 标签对照 `VERIFIED.json` 核对；
   - 学生输入的文字没有改动。
4. **统计**：
   - `verifier_training/v4_report.py` 和 `fd1000_metrics.clustered_difference` 先对每行做 seed 平均，再按源聚类做检验。
   - 已发现并更正一处 bug：里程碑判定误算了 oracle 诊断（commit 4075e2d，更正记录在 `REPORT_test_CORRECTION.json`）。
5. **测试集泄漏**：
   - `train()` 和 `zero_shot()` 只以 `include_test=False` 读数据，有静态测试保证；
   - 测试评估只在 `TEST_FREEZE.json` 之后、每个目标各运行一次。

## 5. 需要三方一起决定的问题

1. **故事定位**。两种讲法：
   - 方法论文："在反事实平衡的可行性判断里，直接判别学不会，中间事实监督让它可学，收益来自测试时把事实写出来"；
   - 系统论文："执行前的拒绝执行门，减少无解场景中的违规"。

   两者需要的证据不同：前者主要靠 2、3、5；后者靠 4、6。
2. **之后用什么测试集**。旧的锁定测试集已经用过。要做新的确认性比较，需要新的锁定测试集（选项 5）；
   否则 2–4 只能报告为探索性结果。
3. **是否扩数据**。现在只有一种不可行证书机制、4 个任务家族、15 个测试源。
4. **预算**：GPU 小时数，以及 Phase 3 是否还要用 API 基线（目前只有 GPT-6 Luna 的验证集结果）。

## 7. Astra 评审后的调整（2026-10-17）

### 7.1 评审要点与核对

Astra 从 Quest 原始预测独立复算了 B − A = +29.69 个百分点，CI [+22.33, +36.78]，与报告一致，哈希也吻合。
Claude 同意评审的全部主要判断：

- **定位**：用证书和安全见证建立可信的约束可行性监督，并研究显式空间关系预测能否帮助判断。
  这还不是一种新的推理训练方法，也还不是可用的安全门。
- **A 是一个没学起来的基线**：三个 seed 最后 32 步的训练判定损失为 0.70–0.71，在训练集上就停在随机水平。
- **C 只给出线索**：不能说明"收益来自测试时推理"。报告原先的这一表述已经撤回。
- **oracle 诊断的设计缺陷**：前缀里包含了 `Separated`，所以 100% 不能证明模型会组合两个关系。
- **错误拆分**：已用原始记录核对，458 / 72 / 45 / 1 完全一致。判定与"把模型自己预测的关系代入程序规则"逐行一致。
- **工程**：B 的纯训练约 14 分钟，验证集上的采样和诊断约 50 分钟。

Claude 补充的一条（验证集，只作描述）：**按见过的事实样本数对齐后，C 的事实读法与 B 几乎相同**。

| 见过的事实样本数 | B 准确率 / 四个事实全对 | C 事实读法 准确率 / 四个事实全对 |
|---:|---|---|
| 512 | 55.6% / 47.0% | 54.5% / 42.5% |
| 768 | 插值约 64.5% / 约 60% | 65.1% / 60.9% |

- C 比 B 低，主要是因为事实监督少，两个目标之间的干扰不大。
- C 的直接分支在训练中同样停在随机水平（判定损失约 0.69）。所以能说的是"事实联合训练没有让直接判定学起来"。

报告（PHASE2_REPORT.md 和 PHASE2_REPORT.html）中过度的表述已经按以上几点改正。

### 7.2 调整后的计划（短周期，只用 train / validation；每一步开始前需要用户确认）

**第 1 步：A 基线能否拟合**（约 1 GPU 小时，不碰测试集）

- 1a：用已保存的 A 第 128、384 步 adapter（3 个 seed）评估训练集：greedy 判定和 P(1)。
- 1b：极小样本过拟合。从 4 个构造格子各取 1 个训练单元，共 16 行；A 和 B 在相同设置下各训练约 150 次更新，看能否拟合。
- 判定规则：

  | A 能否拟合 16 行 | B 能否拟合 16 行 | 结论 | 下一步 |
  |---|---|---|---|
  | 不能 | 能 | 优先怀疑实现问题 | 逐项检查 direct 目标的编码、掩码和损失 |
  | 能，但 512 行拟合不了 | — | 优化停滞（需要学"图像 × 规则"的交互） | 第 2 步加一个事先声明的 A 训练预算变体 |

**第 2 步：简洁对照**（约 3–4 GPU 小时，结果属于开发数据上的验证集结果）

- **三个组，各 3 个 seed**：
  - A：直接判断。如果第 1 步指向优化停滞，再加一个 A 训练预算变体。
  - R：只预测两个包含关系（相对受保护盒），由程序规则得出判定。
  - B：当前完整版本。
- **要回答的问题**：如果 R ≈ B，工作就集中到"关系识别的可靠性"上。
  要主张"测试时生成过程有独立价值"，需要另外设计监督量匹配的对照，这次不做。
- **评估开销**：训练中只做 greedy 验证；K 次采样和改写前提诊断只在阶段收尾、对选定的 checkpoint 做一次。
  修正后的 oracle 只写入两个包含关系。预计 B 每次运行约 20–25 分钟，而不是 64 分钟。
- **免费的附带分析**：在**验证集**的错误上，按遮挡和可见像素数（数据里的 `visibility_prescreen`）分层，
  看包含关系的错误是否集中在小目标或被遮挡的样本上。不使用测试集的错误。

**第 3 步：只选一个针对关系预测的改进**（之后再定）

- grounding（目标/终点的图像坐标、盒子投影角点）或视觉输入（裁剪、提高分辨率），二选一。
- 根据第 2 步的错误分析选择。RL 暂不考虑。

**第 4 步：新的锁定源**（需要单独授权数据采集）

- 设计原则：
  - 增加独立源和布局变化；
  - 破坏"每张图只有一个分隔盒"的固定构造（两个都分隔、都不分隔、嵌套）；
  - 继续要求证书和见证。
- 在任何模型看到之前冻结新的测试集，供确认性比较使用。

B′、组合深度和 AEGIS 拒绝执行门，等第 1、2 步的结果出来再决定。
