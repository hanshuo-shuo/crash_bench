## 2. 和整体研究方向的关系

`docs/new_report.md`（在 `codex/paired-repeats` 分支上）里的 Direction 1 要区分三种情况：

- (a) 任务一开始就不可行；
- (b) 还能恢复，但当前策略不会；
- (c) 执行过程中逐渐失去恢复的机会。

这个 verifier 针对的是 (a)，而且是在声明的约束合同下、有证明的版本：
- 负例有封闭分隔证书；
- 正例有真实的安全轨迹；
- 策略失败一律记为 UNKNOWN，不当作不可行。

## 3. 请 Astra 重点核查

按"如果错了影响最大"排序：

1. **A 的常数预测是不是 bug？**
   - **现象**：3 个 seed 的 verdict 损失都降到 0.70 左右（ln 2），三个检查点都给出常数预测。
   - **该看的代码**：
     - `verifier_training/fd1000_run.py` 的 `encode`：direct 目标、标签掩码、单 token 判定检查；
     - `train`：样本顺序、损失、选模；
     - `fd1000_contract.schedules`。
   - **已有的反证**：
     - preflight 逐行核对过 A/B 的推理输入完全相同、判定是单个 token；
     - 梯度探针显示 verdict 损失能把非零梯度传到 LoRA；
     - B 走的是同一条代码路径，只是目标不同。
   - **还没做的**：用已保存的 A adapter 在训练集上评估。如果连训练集都拟合不了，就是优化问题，而不是过拟合。
2. **C 的设计是否公平**：C 每个 epoch 只有一半样本是事实目标，所以它见到的事实监督只有 B 的一半。
   C 写事实读法低于 B，可能只是因为这个。
3. **数据和标签**：
   - 结构化事实在 `verifier_training/v4_export.py` 里由构造元数据推出，并断言与 `LAYOUT.json` 的几何一致；
   - 标签对照 `VERIFIED.json` 核对；
   - 学生输入的文字没有改动。
4. **统计**：
   - `verifier_training/v4_report.py` 和 `fd1000_metrics.clustered_difference` 先对每行做 seed 平均，再按源聚类做检验。
   - 已发现并更正一处 bug：里程碑判定误算了 oracle 诊断（commit 4075e2d，更正记录在 `REPORT_test_CORRECTION.json`）。
5. **测试集泄漏**：
   - `train()` 和 `zero_shot()` 只以 `include_test=False` 读数据，有静态测试保证；
   - 测试评估只在 `TEST_FREEZE.json` 之后、每个目标各运行一次。

## 5. 需要三方一起决定的问题

1. **故事定位**。两种讲法：
   - 方法论文："在反事实平衡的可行性判断里，直接判别学不会，中间事实监督让它可学，收益来自测试时把事实写出来"；
   - 系统论文："执行前的拒绝执行门，减少无解场景中的违规"。

   两者需要的证据不同：前者主要靠 2、3、5；后者靠 4、6。
2. **之后用什么测试集**。旧的锁定测试集已经用过。要做新的确认性比较，需要新的锁定测试集（选项 5）；
   否则 2–4 只能报告为探索性结果。
3. **是否扩数据**。现在只有一种不可行证书机制、4 个任务家族、15 个测试源。
4. **预算**：GPU 小时数，以及 Phase 3 是否还要用 API 基线（目前只有 GPT-6 Luna 的验证集结果）。

## 6. Claude 的建议

- **先做 1**：最便宜，不碰测试集，直接回答"A 的失败是不是 bug"。
- **然后定一个 Phase 3 组合**：把 2、3、4 放进同一份预注册，统一在新的锁定测试集上评估。
  新测试集通过 5 构建，同时把任务从"两个比特"扩展到组合深度。
- **Phase 4 往后放**：等感知瓶颈缓解、false-feasible 明显下降之后再做。
