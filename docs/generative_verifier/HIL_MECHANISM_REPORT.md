# 机制 pilot 报告：中途切换时，任务信息走哪条路进入 π0.5 的动作专家

2026-11-04。方案和冻结读法见 [HIL_MECHANISM_IDEA.md](HIL_MECHANISM_IDEA.md)（第 7 节冻结于 `3fb6a44`，smoke 见第 11 节）。

## 结论

预先写定的四个读法：

| 读法 | 结果 | 预测 |
|---|---|---|
| P1 工具核对 | `tool_ok` | ✓ |
| P2 t = 0 正对照 | `interface_partial` | `interface_found` ✗ |
| R2 失败格里图像 token 上的任务印记是否变淡 | `mixed` | `image_route_fades` ✗ |
| R3 格内印记能否区分换成功和换失败 | `gap_does_not_predict` | 没有写预测 |

- **P1**：240 个状态上，替换工具与原生 π0.5 一致，结论可以信。
- **P2**：判 `interface_partial` 是因为正对照选得不好。1→8 在 t = 0 时 A、B 都要先去抓碗，第一个动作块几乎相同，20 个状态里只有 4 个能读出 E。另外两对是 0.75 和 0.89；三对的单层峰值都在第 14 层，与 Goodfire 真机选的第 14–16 层一致。
- **R2**：五个失败格全部变淡，γ 为 0.51–0.71，区间上界都 < 1。判 `mixed` 只因为成功格 1→8 在 .25 时区间下界 0.86，没过 0.9 的门槛；另两个成功格反而升到 1.19 和 1.42。
- **R3**：同一格内，图像印记不能区分成败（AUROC 0.62 [0.48, 0.75]）。所以"图像这条路变淡"是**按任务对和时点**出现的现象，不是逐个状态的成败指标，**因果关系还没测**。

**新的描述性发现：两条路。**
- 第 14 层从图像 token 读任务。指令先在第 8–13 层写进图像 token，再在这里被读走。
- 第 16 层直接读文字 token。
- 换得过去的 1→8 中途一直用第 14 层那条图像路。
- 换不过去的格里，图像路几乎消失，B 的影响改走第 16 层的文字路（2→9、7→8 在 .5），或者在任何 3 层窗口里都找不到（7→8 在 .75）。
- 2→9 中途 B 的影响仍然能传到动作专家（总 E 约 0.73），但切换照样失败。所以"信息传到了"不足以完成切换。

## 能说什么、不能说什么

**能说**（π0.5 `pi05_libero`，LIBERO-Goal 三对任务，开环，第一个动作块）：
1. 动作专家主要在第 14 层读任务信息，第 16 层次之，与 Goodfire 在 DROID 检查点上的结论一致。t = 0 时，这些信息主要来自被指令调制过的图像 token。
2. 换得过去的那一对，中途一直走第 14 层那条图像路；换不过去的格里，图像 token 上的任务印记降到 f = 0 的 0.51–0.71 倍，第 14 层几乎读不到 B。这时 B 的影响改走第 16 层的文字路，或者在任何 3 层窗口里都找不到。
3. 2→9 中途 B 对动作的影响仍然能传到（E 约 0.73），切换却失败。所以不能把失败简单归为"新指令没传到动作专家"。

**不能说**：
- **不能说图像路变淡导致了切换失败。** 它和失败是在"任务对 × 时点"的层面上同时出现的。同一格内它不区分成败（R3），而换不换得过去也可能由物理状态决定（Causeway 的 task islands）。要说因果，需要闭环干预。
- **E 不等于做对。** E 衡量的是动作往 B 自己的输出靠了多少；在失败状态上，B 自己的输出本来就做不成 B。
- **范围窄。** 一个检查点，三对任务，每格 20 个状态，只看第一个动作块、开环。

## 偏离和异常

- **代码和读法**：冻结后没有改动。
- **正对照选择**：1→8 在 t = 0 的可读状态很少，这是选正对照时没预料到的（smoke 里只有 1 个状态可读）。读法按冻结规则执行，没有事后换掉这一对。
- **跨作业数值噪声**：原生输出与存档逐位相同的只有 38/240，比 smoke 的 38/40 低；差都 ≤ 0.007，属于跨节点数值噪声，不影响同一作业内的比较。
