# Phase 0–1 报告：数据导出、零样本诊断与 A/B 工程试跑

2026-10-17。读者：项目负责人。只用 validation（192 行、48 个单元、14 个源）；锁定测试集**未加载、未评分**。
计划见 [PLAN.md](PLAN.md)。本文件同时复制在 campaign 根目录。

## 结论速览

1. **Phase 0 完成**。导出数据、合同、训练与测试分离、指标、单元测试、预注册都已实现并通过检查（见下表）。
2. **感知是首要瓶颈，规则应用不是。**
   - 微调过的 B 组（1 个 epoch）和 GPT-6 Luna 都没有出现"事实对但 verdict 错"的样本，各为 0 例。
   - B 组在给出正确事实后，verdict 192/192 全对。
   - 错误几乎都来自"目标/终点是否在受保护盒内"这两个比特：B 组 60%/76%，Luna 70%/88%。
3. **A 组 1 个 epoch 没有学到任何区分信号**：verdict 损失停在 ln2，全部判 0，准确率 50%。
   B 组同样只训练 1 个 epoch，已经到 55.7%（AUROC 0.58），说明事实监督至少让信号开始出现。
   这是单 seed、1 epoch 的工程试跑，**不是科学结论**；正式比较要等 Phase 2（3 个 epoch × 3 个 seed）。
4. **GPT-6 Luna 零样本是目前最强的参照**：直接问法 71.9%，事实问法 73.4%，花费 $0.4669。
5. **工程检查全部通过**：格式学会、梯度正常、没有 NaN、显存 ≤12.3 GiB。
   Phase 2 估计约 7.5 GPU 小时训练加约 4 GPU 小时测试评估。开始前有两处需要调整（§6）。

  按 validation 重算的分层与 PLAN §2.2 完全一致：EXIT×ckpt0 1.000，EXIT×ckpt>0 0.789，ENTRY×ckpt0 0.861，ENTRY×ckpt>0 0.636。
- **`SAMPLES.html`**：8 个训练单元、32 行，放在导出目录 `dataset/` 下，供翻看，不是审核关。
- **token 审计**：

  - 最长序列 808（上限 2048），无截断。

## 5. 1.3 工程试跑细节

**A**（128 次更新，作业 4072824）：
- 格式 192/192。
- verdict 损失从 1.52 降到 0.69（ln2）后停住；validation 的 P(1) 全部落在 0.47–0.50。
- 训练 4.2 min，整个运行 5.9 min，峰值显存 9.3 GiB。

**B**（128 次更新，作业 4074681）：
- 模板 token 损失约 1e-4；verdict 损失约 0：在 teacher forcing 下，verdict 完全由前面的事实决定。
- 关键字段损失从 2.03 降到 0.2–0.43，并且来回波动，即感知比特只学会了一部分。
- 训练 4.5 min，峰值显存 12.3 GiB；greedy 每行 1.85 s、26 个 token。

**B 的诊断读法**（选定的第 128 步）：

| 诊断 | 结果 |
|---|---|
| K 次采样（温度 0.7）平均 P(1) | 准确率：K=1 时 55.7%，K=16 时 56.8%；AUROC：0.575 → 0.614。多数投票不更好。每行 7.6 s |

## 6. 按计划 Phase 1 解读表的判断

| 比特准确率 | oracle 事实准确率 | 含义 |
|---|---|---|
| 低（B 60%/76%，Luna 70%/88%） | 高（B 100%） | **感知瓶颈** |

- 这对应计划中的"感知瓶颈：Phase 3 优先做 grounded CoT 和视觉侧改进"。
- 计划规定 Phase 2 无论如何都会运行；Phase 1 的结果只用来定资源请求，不改动 Phase 2 的设置。
- Qwen 零样本的 oracle 只有 59%。这说明 3B 基座不微调就不会应用规则；微调后的 B 组不存在这个问题。

**Phase 2 开始前需要处理的工程事项**（都不改变预注册的科学设置）：

1. **`evaluate-test` 会超时**：预计约 4 GPU 小时，其中 B/C 的 16 次采样和诊断各约 32 分钟。
   这超过了 `v4_gpu.sbatch` 的 4 小时上限，需要按 run 拆成多个作业，或者单独提高时限。
2. **采样的输出方式**：16 次采样每行 7.6 s，主要是每一步都输出全词表 logits。
   可以改成只保留 verdict 位置的两个数字 logits。
3. **report-test 统计脚本**：预注册里提到的读数基线在测试集上的重拟合，以及按对错分层的诊断，
   要在 freeze 之前写好并测试。
4. **C 组还没在 GPU 上真正训练过**：混合目标训练和两种强制前缀读法只在单元测试里跑过。
   建议 Phase 2 先做一次 C 的短 smoke。
5. **资源估算**：A 每次约 18 min，B 约 64 min，C 约 68 min。9 次运行约 7.5 GPU 小时，2 张卡大约 4 小时（不含排队）。

## 7. 限制

- 单 seed、1 epoch、validation 只有 14 个源，所有数字都只是工程读数。
  validation 上单元级可检测的差异大约在 20 个百分点以上。
- 零样本问法给了任务说明和格式说明，和训练输入不同；它只是诊断，不是公平的同条件比较。
- Luna 每次都用默认的 medium 推理（平均约 2,250 个推理 token），没有对推理强度做任何选择。
