## 2. 设计

- **任务**：LIBERO-Goal 10 个任务共用一个场景（7 个物体完全相同，已核对 BDDL）。所有有序对 (A, B)，A ≠ B，共 90 对。
- **前缀**：每个任务 A 在官方初始布置 0–9 上用自己的指令跑一遍（`hil_suite_run` 的 prefix 阶段，种子 `hil_suite.policy_seed`，与阶段 1 同一规则），每一步都记录另外 9 个任务的目标是否成立。共 100 条前缀。A 没做成的前缀不分支，计数排除。
- **切换点**：f = 0（等待步之后）、0.5、0.75（A 自己策略步数的一半、四分之三），与阶段 1 的 `checkpoint` 相同。
- **排除**：切换步上 B 的目标已经成立（前缀磁带上可读出）的单元，在计划时排除并计数。
- **臂**：

  | 时点 | 臂 |
  |---|---|
  | f = 0 | native（上限，也是图像 gap 的起点） |
  | f = 0.5、0.75 | native、amp2（修复：第 12–14 层图像 token 的 K/V 沿 B − A 放大到 2 倍） |

- **规模**：每对每个初始布置 5 次，最多 90 × 10 × 5 = **4,500 次**；smoke 只用初始布置 0、B = (A + 3) mod 10，共 50 次。
- **协变量**（切换步上，在前缀磁带上读出，运行前写进计划）：
  - **phase75**：时点是 0.75；
  - **same_object**：A 和 B 的目标操作同一个物体（碗：1、3、4、8；酒瓶：2、9；其余各不相同）；
  - **gripper_closed**：夹爪开度（左右手指关节之差）< 0.05（张开约 0.08，夹着碗或酒瓶约 0.015–0.025）；
  - **must_release**：夹爪闭合且 A、B 不是同一物体（要先放下手里的东西）；
  - **γ**：请求 1 上第 12–14 层图像 token 的 ‖V_B − V_A‖ / ‖V_B‖，除以同一对、同一初始布置 f = 0 的值（native 运行，服务端日志）。

## 5. 读法

第 5 节状态：已冻结（2026-11-09，提交前）。

**单位**：状态 = (A, B, 初始布置, 时点)；格 = (A→B, 时点)。

**可读的对与格**：
- 对的 f = 0 格至少 5 个状态、native 成功率 ≥ 0.5，这一对才算**可读**（否则 `ineligible`）；
- 可读对在 0.5、0.75 的格至少 5 个状态才读（否则 `thin`）；
- 格的分类按 native 成功率：≤ 0.5 失败格，≥ 0.9 成功格，其余中间格。

**统计**：两层 bootstrap，先有放回地重抽任务对，再在每个被抽到的格里重抽状态，2000 次，种子 0；同一对被抽到两次算两对。

**C1 工具核对**（smoke 和正式都要过），`tool_ok` 需要以下全部成立：
1. 每次运行都完成，哈希核对通过，结果能由轨迹重算出来；服务端日志与客户端逐请求一致；臂被服务端原样确认；
2. 切换步的物理哈希与前缀磁带同一步相同；
3. 请求 1 上，干预程序在 λ = 1 时与 `Policy.infer` 的 L∞ 差：中位 ≤ 0.01，最大 ≤ 0.05；
4. native 没有任何 K/V 改动，请求 1 的动作与 λ = 1 相同；
5. amp2 每次请求的 K/V 改动 ÷ ‖B − A‖ 与 1 的差 ≤ 0.001，请求 1 的动作块与 λ = 1 时不同；
6. 实际用的指令都是 B；没有单元在切换步上 B 已成立；
7. 跨环境目标核对通过（`STATE_CHECK.json` passed，至少一次核对）。

只报告：同一状态两个臂的第一个策略输入哈希相同的比例（渲染可能差一个灰度）；与阶段 1 在共有的对和初始布置上的格成功率对比；排除的单元数。

**S1 普遍性**：0.75 时可读格里失败格的比例：
- ≥ 0.25：`common`；≤ 0.10：`rare`；其余 `occasional`。
- 0.5 时的比例、ρ（中途 ÷ f = 0，状态配对）只报告。
预测：`common`（阶段 1 的 Goal 8 对里，0.75 时 3 对失败）。

**S2 修复的推广**（失败格，**不含**试点三对 1→8、7→8、2→9），增益 = amp2 − native：
- `restores_switch`：增益区间下界 > 0 且增益 ≥ 0.15；
- `weakly_restores`：区间下界 > 0，增益 < 0.15；
- `harms`：区间上界 < 0；
- `no_restore`：其余情况（没有失败格时 `insufficient`）。
预测：`restores_switch`，增益小于试点（试点 +0.52，留出 +0.20）。

**S3 选择性**（成功格，不含试点三对），改变 = amp2 − native：
- `selective`：区间下界 ≥ −0.10；
- `damages`：区间上界 < 0 且改变 ≤ −0.10；
- `unclear`：其余情况。
预测：`selective`。

**S4 失败由什么决定**（可读的 0.5、0.75 格，γ 有定义的 native 状态）：
- **S4a 跨格**：格的 γ 中位数与 native 成功率的 Spearman 相关：
  - 区间下界 > 0：`fade_tracks`；上界 < 0：`reversed`；其余 `unclear`。
- **S4b 超出物理因素**：状态层面的逻辑回归（L2 惩罚 1，截距不罚），native 是否换成功 ~ phase75 + same_object + gripper_closed + must_release + 标准化的 log γ；系数区间用按任务对的 bootstrap：
  - log γ 系数区间下界 > 0：`beyond_physics`；
  - 否则，任一物理协变量的区间不含 0：`physics_explains`；
  - 其余 `unclear`。
预测：S4a `fade_tracks`，S4b `beyond_physics`。

**只报告、不作读数**：
- S2 含试点对、只看试点对、按时点分开；中间格的 amp2 − native；S3 含试点对；
- 失败格里 native 失败时把 A 做完的比例；
- 修复增益与格的 γ、native 成功率的 Spearman，按 same_object、夹爪闭合、时点分组的平均增益，增益 ≥ 0.3 的失败格比例；
- 只用物理协变量与加上 log γ 的模型的样本内 AUC；
- 每格的状态数、两个臂的成功数、γ 中位数、夹爪闭合比例、类别。

**解读规则**（写在运行前）：
- **S1 `common`**：中途换不过去在 Goal 的任务对里普遍存在，不是挑出来的几对。`rare`：试点和阶段 1 的失败格是少数情况，论文的现象部分要相应收窄。
- **S2 `restores_switch` 且 S3 `selective`**：固定的修复推广到整个任务对空间，给出一个不是挑出来的修复数字。`no_restore`：修复只在少数对上有效，主张收窄到那些对。
- **S4b `beyond_physics`**：在进度、接触和"要不要先放下"之外，图像路的变淡还能多解释失败，支持"任务条件响应变弱"是失败的原因之一（因果方向由剂量批次和闭环批次回答）。**`physics_explains`**：失败差异主要由物理状态解释，图像路的变淡至多是伴随现象；论文里把机制部分写成"补强能补偿"，不写成"变淡导致失败"。
- 普查只有 native 和 amp2，没有随机对照；修复的特异性由闭环批次（rand2）和修复批次（actrand）在试点格上给出，本批次不重测。
