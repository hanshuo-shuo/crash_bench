## 1. 重点

### 1.1 现在在哪

- **现象站住了**：LIBERO-Goal 全部 90 个有序对，中途换指令 22.8% 换得过去，从起点换是 98.0%。同一物体的对 59.6%，不同物体的对 16.2%。（[普查报告](HIL_MECHANISM_CENSUS_REPORT.md)）
- **这个现象别人也报告了**：Causeway 在同一个 π0.5、同一个 LIBERO-Goal 上，不干预是 26.0%。
- **我们现有的修复当不了方法**：放大 2 倍在全部状态上是 22.8% → 26.7%。它多数时候只是把旧任务打断，手臂并没有去新任务那边（11-14 事后分析）。
- **撤回一句话**：11-12 写的"失败有两层：没听见，和听见了但做不了"没有证据。放大后"两个都没做成"的运行里，到过新任务干活位置附近的只有 26%，和压根没理新指令的运行（24%）一样。
- **第 1 步补上了见证（11-15）**：换指令时先用脚本把手臂退回起始位姿，再让 π0.5 做新任务，1,764 个中途状态里 88.3% 做成（不干预 22.8%，放大 26.7%）。所以这些状态下新任务做得成，失败出在手臂所处的状态。
- **只放下、抬高 10 cm 不够**：全部状态 30.5%，失败格 18.8%。手臂要回到起始位姿附近。
- **例外是旧任务改了场景的时候**：旧任务是"打开上层抽屉并把碗放进去"时，退回也只有 29.6%（抽屉开着）；其余九个旧任务合计 94.3%。有两对（3→1、3→8）退回反而比不干预差。
- **仍然不能说**模型在原来的状态下"听见了"或"没听见"新指令。
- **别人做到哪**：换任务，Causeway 不训练做到 61.6%，ReSteer 靠训练；停下，ELLSA 和 VITA-E 做到 94–100%，但都是专门的结构。细节见附录 A。

### 1.2 故事线（方向 b）

1. **问题**：一个扁平的 VLA（没有上层模型）在任务中途基本不理会新的指令。换成另一个任务大多失败；"停下""回原点""别做了"照做不到 1%。（已有：普查、HIL 套件）
2. **原因的线索**：训练数据里每一局只有一条指令，从头到尾不变。模型在任务中途的状态上没见过"指令和正在做的事不一致"。（推断，不是结论；第 1 步给一半证据）
3. **方法**：一次后训练。老师数据全部由脚本动作加模型自己已有的技能生成，不用人采数据，不改结构，不加上层模型。同一份数据教会它几种中途指令：换任务、回原点、停下、放下。（第 2 步，没批准）
4. **结果**：换任务的成功率要比 Causeway 和 ReSteer 式的对照高；其余几种指令照做；原任务不掉；推理不变慢。

### 1.3 和别人比，哪里不一样

按 11-14 读全文后的情况，如实写：

| 我们想主张的 | 别人有没有 | 还剩多少 |
|---|---|---|
| 换任务做得更好 | Causeway 61.6%（不训练），ReSteer（训练，做法和我们的第 2 步几乎一样） | 要靠数字赢 |
| 没训练过的中途状态也能换 | ReSteer 没测 | 有。留出任务对太容易（退回这个动作和新任务是哪个无关），所以改成留出整个旧任务（第 2.4 节）。Goal 只有 10 个任务 |
| 比"指令一变就跑脚本"好 | 这是零训练的做法，88.3% | 换任务的成功率上最多打平，要靠别的（第 1.5 节风险 2） |
| 不用人采数据、推理零开销 | ReSteer 也是 | 不算差异 |
| 停下、回原点、放下 | ELLSA、VITA-E 能停，靠专门结构；Hi Robot 靠上层模型。Causeway 和 ReSteer 不覆盖 | "同一个扁平模型、同一次后训练"是新的；单看"会停"不新 |
| 几种指令一起训练，换任务本身更好 | 没人测 | 假设，没有数据 |
| 同一物体的对 | Causeway 排除了 | 我们有数据（59.6%） |

所以论文的主数字是换任务，其余几种指令是覆盖面。

### 1.4 门槛和保底

- 全部 90 对上明显超过 Causeway 的 61.6%（比如 75% 以上），没见过的对也接近，原任务不掉，其余指令照做 90% 以上：可以投主会。
- 换任务只到 50–60%：和已有工作持平，靠覆盖面写，档次降一级。
- **保底**：现有结果加第 1 步，写一篇分析型论文，讲中途指令为什么不被执行、为什么通用引导没用、回到入口状态有没有用。
- 这些门槛是 Claude 的估计。训练还没跑过，没有数据说明能到多少。

### 1.5 风险

1. **"教了就会"不稀奇**。"停下"这类话模型从没学过，从头说也是 0 / 118。论文里必须有"策略外的关键词加脚本"这一行基线，并说明模型内解决多出了什么。
2. **脚本退回已经很高（88.3%），这是现在最大的风险**。起始位姿在真实系统里是已知的。换任务时"指令变了"比一下字符串就知道，不需要判断。所以"指令一变就跑脚本回起始位姿，再重新下指令"是一个零训练的现成做法，数字比 Causeway 的 61.6% 还高（设定不同）。
   - **换任务的成功率上，训练出来的模型最多和它打平**。老师就是脚本。按第 2.4 节的取法，1,764 个状态里有老师的是 1,613 个（91.4%），这是学生的上限。
   - **步数上也赢不了（11-15 事后核对，改口）**。之前把"每次多花约 40 步"列为脚本的短处，这不对。从换指令到做成新任务，`home` 的中位数是 142 步（含脚本段），不干预而换成功的是 151 步。两边都成功的 371 个状态上是 126 步对 155 步，其中不干预更快的只有 165 个。每个状态挑最快的那条，中位数也只到 138 步。
   - **脚本剩下的短处**（都有数据）：
     - 手里的东西直接掉下去（B 的物体被碰动时成功率 75% 对 89%）；
     - 旧任务改了场景时不管用（旧任务 3：29.6%）；
     - 有的状态退回反而更差：不干预能换、退回后不能换的有 32 个，其中 13 个在 3→1（不干预 94%，退回后 22%）；
     - "停下""放下"这类指令它不管，要另写关键词和脚本。
   - **所以训练的卖点只能是这三条**：同一个模型、不加外部模块，照做几种中途指令；在脚本失败的状态上不比脚本差；原任务不掉。
   - **如果小规模试跑里学生明显低于脚本**，这条线按保底写：分析论文，主结论是"一个简单的脚本基线超过已发表的方法"，训练只作为"这个修法能蒸馏进模型"的补充结果。
3. **只有仿真和一个模型**。Causeway、ReSteer、Hi Robot、VITA-E 都有真机。没有真机至少要加第二个模型或第二个任务集。
4. **训练的工程没打通**：openpi 的训练在 Quest 上没跑过。

**11-15 改了四处**。Claude 指出原草图的三个漏洞（学生最多学成老师，而老师就是脚本；和 ReSteer 太像；留出的任务对太容易），提了四条修改，用户说："都可以改 按照你的来吧"。这是同意改设计，不是批准训练。

| 改动 | 原来 | 现在 |
|---|---|---|
| 老师数据 | 只用 `home` 的成功轨迹 | `home` 成功就用它，否则用已有的不干预或 `release` 的成功轨迹 |
| 主表 | 和不干预、Causeway 比 | 直接和"指令一变就跑脚本"比 |
| 留出 | 留出任务对 | 留出整个旧任务，加测没训练过的时点 |

**教哪几种指令：**

| 指令 | 老师数据怎么来 | 纳入吗 |
|---|---|---|
| 换任务 | 见下面"老师数据怎么取"；从换指令那一步起整段标成指令 B | 主结果 |
| 回原点 | `home` 臂的脚本段 | 纳入 |
| 停下 | 保持不动 | 纳入 |

| 放回原处 | 模型没有记忆，看不到原位置 | 不纳入 |
| 中途加规则（别越线） | 需要空间判断，属于 verifier 那条线 | 不纳入，写成局限 |

**老师数据怎么取（换任务）：**

- **规则**：每个中途状态，`home` 成功就用 `home` 那条；`home` 不成功而不干预成功，用不干预那条；再不行用 `release` 那条。全部来自已有的运行，不用为它新跑。
- **数量**（事后统计，`experiments/mechanism/retreat_posthoc.py` 的 `teacher` 表）：1,764 个状态里 1,613 个有老师（91.4%）。其中 `home` 1,558 条，不干预 32 条，`release` 23 条。覆盖 86 对，83 对里八成以上的状态有老师。
- **没有老师的 151 个状态**：86 个是旧任务 3（抽屉开着）。旧任务 3 不再整体排除：有成功记录的 76 个状态照常用，评测时单独报告。
- **为什么是 `home` 优先，不是最短的优先**：最初想挑最短的成功轨迹，让模型在步数上赢过脚本。核对后不成立（第 1.5 节风险 2）。`home` 优先让同类状态下的示范一致；另外两种只补 `home` 失败的状态，比如 3→1 里有 13 个状态用的是不干预那条。模型从这里学"什么时候不用退"。

**留出和评测：**

- **留出整个旧任务（主要证据）**：建议留出旧任务 4（把碗放到柜子顶上）和 7（打开炉子），写训练方案时冻结。它们的中途状态在训练里从不配别的指令。
  - 选这两个的理由：4 是四个拿碗的任务之一，留出后同一物体的对也在测试里（4→1、4→3、4→8）；7 不抓东西，不干预时最难换（12 / 180）。都不是旧任务 3。
  - 留出后训练用 8 个旧任务的 1,274 条老师轨迹。
  - 测试直接用普查的这 360 个状态（18 对）。不干预、放大、`home`、`release` 在这些状态上的结果都已存档，不用新跑前缀。
- **没训练过的时点和初始布置**：时点比如 f = 0.35、0.6、0.9，初始布置 10–19。这要新跑前缀，是新数据，要用户点头。
- **不再单独留出任务对**。退回这个动作和新任务是哪个无关，留出一对证明不了什么。
- **其余指令**：回原点、停下、别做了，用 HIL 套件阶段 2 的判定，代码现成。
- **原任务成功率、推理耗时**照常报告。

**先做便宜的一步**（11-15 已批准，执行细节以[训练方案](HIL_TRAIN_PROTOCOL.md)为准；它在训练旧任务里另留了初始布置 9 当开发集，所以老师轨迹是 1,144 条）：

1. 把存档的老师运行重放一遍并渲染图像，转成训练数据的格式。存档里只有动作和物理状态，没有图像；重放是确定的，物理状态可以逐步核对。
2. openpi 的训练在 Quest 上跑通（几十步的冒烟）。
3. 小规模 T1：用 8 个旧任务的老师数据训练，在留出的 360 个状态上评测（约 2 GPU 小时）。
4. 看 T1 在留出状态上离脚本基线（335 / 360）和不干预（87 / 360）各有多远，再决定要不要训 T2 和全量评测。

**判停**（阈值是 Claude 的估计，写训练方案时冻结）：
- T1、T2 在留出状态上都不超过不干预 + 15 个百分点，转保底。
- 超过了但比脚本基线低 20 个百分点以上，停下来和用户商量是否改成"脚本基线为主、蒸馏为辅"的写法（第 1.5 节风险 2）。
