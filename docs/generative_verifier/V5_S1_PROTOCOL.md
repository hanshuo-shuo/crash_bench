## S1a：补布局（CPU）

- **源**：C0 回放里 object/II/task1 的 18 条源，沿用冻结切分：训练 10、验证 4、测试 4。
- **布局**：每条源 8 个设计式布局，共 144 个，种子为 `sha256(源|布局编号|v5-layout-s1)`。构造、见证核验、标签都与 v3 和 S0 相同（[V5_LAYOUT_PROTOCOL.md](V5_LAYOUT_PROTOCOL.md)）。
- **新增记录**（不改变任何标签）：
  - 渲染时核对用：每个叠放组的位移、摆好后的物理哈希、每个 checkpoint 的物理哈希；
  - 机器人底座（`robot0_link0`）的水平位置；
  - 每行加三个字段：
    - T：物体在连线靠机器人底座一侧吗？
    - G：终点在靠机器人一侧吗？
    - 机器人底座到连线的距离。
    - 判定按构造等于 T ≠ G。
  - 每个布局的 checkpoint 几何（`TRACE.json.gz`），留给 S2 用。
- **可用行**：余量 ≥ 5 cm + 0.1 × 抬起高度，并且机器人底座离连线 ≥ 10 cm（否则"靠机器人一侧"说不清）。
- **读数**（训练、验证、测试分别报告）：
  - 合法率；
  - 静置行数（抬起 < 5 cm）；
  - **严格孪生单元**：只看本切分的静置可用行，在"规则 × 进度段"组内两种标签都有；同一 checkpoint 上分隔、不分隔的规则都有，就算一个单元。报告单元数和贡献单元的源数；
  - 训练切分的反事实行数，以及"规则 × 进度"查表能拟合的上限。
- **读法**：
  - 验证和测试各有 ≥ 150 个严格孪生单元，并且各至少 3 条源有贡献 → `s1_supply_ok`；
  - 否则 → `s1_supply_low`，报告后讨论，不自动加布局。

## S1b：渲染（GPU）

- **选样**：在任何渲染之前由启动器确定。
  - 只从 4 条验证源的 S1a 布局里选。这些布局 Claude 没有看过。
  - 测试源的布局只做统计，不渲染、不看。
  - 选 20 个严格孪生单元。在 4 条源之间轮流选，同一条源内先选还没用过的布局，顺序按 `sha256(源#布局|checkpoint)` 排序。
  - 每个单元选两条规则，一条分隔、一条不分隔，各在候选里按 `sha256(源#布局|checkpoint|规则)` 取第一个。
- **回放**：
  - 从规范初始状态出发，按 S1a 记录的位移摆好锚点，摆好后的物理哈希必须一致；
  - 再回放动作带，每个 checkpoint 的物理哈希都必须与 S1a 一致，不一致即停止。
- **学生图**：每个单元三张，448×448，不画任何标注。
  - `overview_a`、`overview_b`：与第 2 步相同。55° 仰角，两张对向，方位角由 `源#布局|checkpoint` 的哈希确定。取景包括目标、终点和这个 checkpoint 上所有候选规则的锚点。
  - `top`：正俯视，图像上方是远离机器人的方向（世界 +x）。取景在上述物体之外还包括机器人底座，所以机器人在图的下方。
- **诊断图**：三张都另存一份，画出两条规则的连线，不进入学生输入。
- **核对**：用渲染时刻的几何重新计算标签和两个事实，与 S1a 的行对照。用实例分割统计各物体在每张图里的像素数。

## 盲看（Claude，两轮）

- **审阅表** `REVIEW_SHEET.json`：只有单元编号、任务文本、两条规则的文字（顺序打乱）和图像路径。不含标签、事实和诊断图。
- **每条规则回答三项**，每项三选一（是 / 否 / 看不出）：
  1. 被搬的物体在这条连线靠机器人的一侧吗？
  2. 篮子在这条连线靠机器人的一侧吗？
  3. 判定：分隔（不可行）/ 同侧（可行）/ 看不出。

  另外记录两个锚点能否认出，以及一句理由。
- **第 1 轮**：只看 `overview_a` 和 `overview_b`。写入 `verifier_dataset/reviews/v5_s1_blind_review_pass1.json` 并提交。
- **第 2 轮**：加上 `top`，重新回答全部问题。写入 `verifier_dataset/reviews/v5_s1_blind_review_pass2.json` 并提交。
- 两轮都提交后，才读 `UNITS.json`、`RENDER_GEOMETRY.json` 和诊断图，写错误分析。

Claude 是一个前沿视觉语言模型。这个结果是"仔细看图能不能判断"的参考，不是人工审阅，也不是训练后学生的上限。

## 读数与事先写定的读法

**读数**（每轮分别报告）：

| 读数 | 内容 |
|---|---|
| R1 | 判定的回答率（不是"看不出"的比例） |
| R2 | 判定的准确率（回答了的里面） |
| R3 | T、G 两个事实各自的回答率和准确率 |
| R4 | 两个锚点都认得出的单元比例 |
| R5 | 每张图里目标、终点、锚点的像素数 |
| R6 | 渲染时刻的标签和事实与 S1a 的一致率 |

渲染时刻与 S1a 不一致的规则，单独列出，不计入 R2 和 R3。

**读法**：
- **判定**：任一轮 R1 ≥ 0.75 且 R2 ≥ 0.85 → `relation_visible`，否则 `relation_hard`。
- **事实**：任一轮 T 和 G 的回答率都 ≥ 0.75、准确率都 ≥ 0.85 → `facts_readable`，否则 `facts_hard`。
- **俯视图**：满足下面任一条，S2 的学生输入就用三张图；否则用两张斜视图，与 V4 相同。
  - 第 2 轮相对第 1 轮，判定的回答率提高 ≥ 0.10，或准确率提高 ≥ 0.05；
  - T、G 的回答率或准确率按同样的门槛提高。
- **下一步**：
  - 两个读法都通过 → 写 S2 协议；
  - 事实读法不通过 → 回到事实设计讨论，例如换参照物，或改用后备方案（图上定位加程序判定）。
