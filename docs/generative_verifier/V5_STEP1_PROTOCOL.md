# V5 第 1 步协议：CPU 几何摸底

2026-10-24 写定，在看到任何结果之前冻结。计划见 [V5_PLAN.md](V5_PLAN.md)。
用户 2026-10-24 批准开始这一步（"推送+开始第一步 故事是最重要的"）。

## 这一步为故事回答什么

V5 想讲的故事：

> 在自然场景里，约束用自然语言指向真实物体。直接训练判定的模型会学到捷径，换一条规则就错；
> 先写关系事实的模型读的是场景，换规则也对；规则越多，差距越大。

要讲这个故事，数据必须同时满足三件事：

1. **标签要看图才知道**：同一个任务、同一条规则，在不同场景里有时可行、有时不可行。否则只读文字就能猜对。
2. **有规则翻转孪生**：同一张图配两条规则，一条把目标和终点隔开，一条不隔开。
3. **有深度变化**：一张图配多条规则时，起分隔作用的可以是 0、1、2 条。

这一步只用几何检查 SafeLIBERO 的真实物体能不能提供这三样，不渲染图像、不训练模型、不调用 API、不产生训练数据。

## 输入

- **A 部分（初始状态）**：官方批次的全部 1,600 个初始状态（4 个 family × 2 个 level × 4 个任务 × 50 个 episode）。
  每个状态用 `set_init_state` 加 20 步空动作（夹爪张开）静置，与 V4 的 `make_env` 相同。
- **B 部分（执行中途）**：V4 两个 constraint-batch 根目录下的 67 条源轨迹
  （`20261015T013004Z_constraint-batch_96a99b51efaa`、`20261015T013009Z_constraint-batch_96a99b51efaa`），
  读取 `execution/SAMPLES.jsonl.gz` 里每一步的目标物体材料点和终点位置。锚点位置取 A 部分同一初始状态的值。
  B 部分对应的情景是：机器人做到一半，来了一条新规则，问还能不能守着规则做完。

## 定义

- **在场物体**：世界坐标 |x| < 1 m、|y| < 1 m，并且碰撞包围盒底面高度在桌面高度 s 的 [s − 0.06, s + 0.40] m 内。
  s 取在场范围内所有物体包围盒底面高度的中位数。
- **目标与终点**：任务目标里每个 `on`/`in` 原子，第一个参数是目标物体，第二个是终点。
  - A 部分：目标点取目标物体包围盒中心；终点是物体时取包围盒中心，是 site 时取 site 位置，找不到 site 时取去掉区域后缀的父物体。
  - B 部分：目标点取 `native_point`（材料点），终点取 `receiver_position`。
- **锚点**：在场物体中排除以下几类：
  - 目标物体、终点物体，名字里含 `base` 的底座；
  - 中心词出现在任务文本里的物体（中心词是去掉编号、`obstacle`、`small` 之后的最后一个词，例如 `red_coffee_mug_obstacle_1` → `mug`）；
  - 与另一个在场锚点中心词相同的物体（指代不唯一）。
- **R-line(A, B)**：过两个锚点水平中心的竖直平面。两锚点水平距离至少 0.10 m。
  - 目标点和终点在平面两侧，记为分隔（不可行候选）；
  - 余量取两点到平面水平距离的较小值。
- **R-zone(A, r)**：锚点水平包围盒向外扩 r 的竖直柱体，r ∈ {0.05, 0.10} m。
  - 目标点和终点恰有一个在柱体内，记为分隔；
  - 余量取两点到柱体边界水平距离的较小值。
- **多个目标原子**（long 任务）：任一原子分隔即为分隔，余量取所有原子中的最小值。
- **规则键**：模板加锚点类别名（去掉编号），R-zone 再加 r。**文字分组**取（任务，规则键）。
- **余量门槛**：主分析 0.05 m，敏感性分析 0.03 m。余量不够的行不计入统计。
- **B 部分的 checkpoint**：与 V4 相同，`range(0, T − 10, 5)`，T 是轨迹动作数。
  - 对没有分隔的行，如果从这个 checkpoint 到结束，目标点在所有积分子步上都没有越过平面或柱体边界，记为**有见证**。
  - 对分隔的行，如果轨迹仍然完成了任务，它必然越界。不越界的计数应为 0，用来检查几何实现。

## 读数

两部分都报告以下读数，并按 family 和模板分开：

| 读数 | 含义 |
|---|---|
| R1 只看文字的上限 | 按文字分组取多数类，能猜对的比例（Bayes 上限） |
| R2 平衡后的产出 | 每个文字分组取 2·min(n₀, n₁) 行后的总行数，以及贡献这些行的不同源数。只看文字的准确率在这部分上按构造为 50% |
| R3 孪生 | 有多少个状态（B 部分是 checkpoint）同时有一条分隔、一条不分隔的规则，并且两条规则所在的文字分组都两种标签都有 |
| R4 深度 | 每个状态里，来自"两种标签都有"的分组的规则，两两组合后 0/1/2 条分隔的组合数，以及能提供每种组合的状态数 |
| R5 时间捷径（仅 B） | 在文字分组上再按归一化时间 t/T 分 5 段后的 Bayes 上限，以及平衡后的产出 |
| R6 见证（仅 B） | 平衡后的产出里，不分隔的行有真实见证的比例 |

## 事先写定的读法

- **A 部分 R1 ≥ 0.90 → `initial_layout_fixed`**：SafeLIBERO 的初始布局几乎固定，只用初始状态做不出看图才能判断的标签。
  故事需要执行中途的 checkpoint，或者新的布局。
  R1 < 0.90 时，按平衡后的产出判断：至少 100 个初始状态有贡献，记为 `initial_layout_viable`，否则 `initial_layout_insufficient`。
- **B 部分按"文字 × 时间段"平衡后：至少 30 个源有贡献，平均每个有贡献的源至少 6 行，且 R6 ≥ 0.8 → `checkpoint_design_viable`**：
  下一步做小样本渲染，确认这些关系从两张图里看得出来。
  参照：V4 是 64 个源、平均每源 14 行。V5 正式采集可以用 838 个有历史安全成功的初始状态。
- **A、B 都不可用 → `natural_anchor_insufficient`**：退回桌面标记，或者采集新布局（需要单独授权）。
  任一可用时，总读法为 `proceed_to_render_pilot`。

这些读法只决定下一步做什么，不是数据集的验收标准。
