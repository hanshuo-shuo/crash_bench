## 1. 要回答的问题

S3 里，B 从事实推结论完全正确，错在两个"机器人侧"事实上；两组连训练集都没超过"规则 × 进度"查表。原因有两种可能：

1. **看不出**：3B 模型在两张 448 像素的斜视图上分不清这两个事实，或者 V5 目标的编码、掩码有问题；
2. **没练够**：一个 epoch、1,792 行的训练太少。

这一步先看最基本的一件事：**在少量训练图上反复训练，B 能不能把这两个事实背下来**。
- 背不下来：先查编码；编码没问题，就说明问题在看图，应该换事实的写法。
- 背得下来：管线没问题，S3 的失败属于泛化或训练量的问题。

另外再看一项**迁移**：背下来以后，换到没参与训练的训练图上，两个事实能不能超过查表。这一项可以提示"能不能看"，但证明不了。只用 32 张图训练，学不出能迁移的读法，也是可能的。

- **授权**：用户 2026-10-25（"做一下吧"）。
- **不做的事**：
  - 不评估验证集和测试集；
  - 不调用 API；
  - 不做超参数搜索。

## 4. 读数

- **拟合**：在每个评估时刻，对拟合集做贪心生成（和 S3 一样，不给金标前缀）。读出判定准确率、两侧都对的比例，以及每个事实的准确率。
- **拟合损失**：最后一次更新后，在拟合集上用 teacher forcing 读两个事实值 token 的交叉熵，取平均（eval 模式，不开 dropout）。
- **迁移**：最后一次更新后，在留出集上用 teacher forcing 读两个事实：给定金标前缀，比较事实值位置上 P(yes) 和 P(no)。
  - 每个事实的增益 = 准确率 − 查表准确率；迁移增益 = 两个事实增益的平均；
  - 以图像为单位做 bootstrap，给出 95% 区间。
  - 篮子侧的读数用的是金标物体侧前缀，和贪心生成不完全一样。
- **参照**：S3 选定的 B adapter（seed 713）也用同样方法在留出集上读一次。它在 S3 训练中见过这些行一次。

## 5. 判定规则（作业开始前冻结在 `config.json`）

**每次运行**（看最后一次更新）：

| 类别 | 条件 |
|---|---|
| 能拟合 | 贪心判定准确率 = 1，两侧都对 = 1，并且拟合损失 < 0.1 |
| 不能拟合 | 两侧都对 ≤ 0.6，或者拟合损失 ≥ 0.5 |
| 部分 | 其他情况 |

- **每个规模的结论**：3 个 seed 中至少 2 个同类，就取该类；否则记为 mixed。
- **迁移**：取 64 行三次运行的迁移增益平均。≥ 0.10 记为"看到迁移"，否则记为"没有迁移"。

**决策表**：

| 16 行 | 64 行 | 迁移 | 结论 | 下一步 |
|---|---|---|---|---|
| 不能 | — | — | `cannot_fit` | 先查 V5 目标的编码、掩码和损失；都对的话，说明 3B 在这两张图上分不清这两个事实，换事实写法（选项 3） |
| 能 | 不能 | — | `fits_16_only` | 只背得下极少的题：倾向选项 3 |
| 能 | 能 | ≥ 0.10 | `fits_and_transfers` | S3 是训练不够；下一步选项 2（3 个 epoch） |
| 能 | 能 | < 0.10 | `fits_without_transfer` | 能背但不迁移，模型在记图而不是读线。选项 2 仍是直接检验，但更可能需要选项 3 |
| 其他组合 | | | `inconclusive` | 如实报告，讨论后再定 |
