  - A 连 16 行都拟合不了，3 个 seed 都停在 50%，判定损失约 0.69；

## 3. 按协议做的实现检查（CPU，无训练）

在一行训练数据上逐个 token 解码，并对 A 与 B 各做一次损失移位检查：

- **A 的监督 token** 正好是 `Ver` `dict` `:` ` ` `0/1` `<|im_end|>`，判定掩码只覆盖数字这一个 token。
  B 的判定部分与 A 相同，只是前面多了四行事实。
- **损失移位正确**：把 logits 设成在每个位置都完美预测下一个金标 token，A 和 B 的总损失与判定损失都为 0。
- **输入**：A 与 B 的推理输入完全相同。Phase 2 preflight 已逐行核对；本次作业又核对了 512 行的哈希。
- **两个通路都能工作**：
  - B 能学会依赖图像的事实，例如"目标在受保护盒里"，所以图像信息确实进入了语言模型；
  - B 能从规则文字里抄出受保护的颜色，所以文字通路也在工作。
- **同一个图像对的两行**，规则文字只差一个颜色词（orange ↔ purple），标签相反。

**结论**：没有找到会让 A 学不到东西、而 B 不受影响的编码、掩码或损失错误。

## 4. 解读与限制

- **构造上的原因**：
  - 每个四行单元里，单看规则颜色词、单看图像（两种配色）都给不出任何标签信息，只有两者的交互可以。
    这排除的是单模态捷径。A 同时看到两种输入，50% 不是它的信息上限：学会"受保护盒是不是分隔盒"的模型四种情况都能答对。
  - 反事实平衡可能使当前模型较难从最终标签中学到有效的图文交互；是否表现为梯度信号弱或相消，尚未测量。
    初稿写的"一阶成分正好互相抵消"过强：它只对梯度里"图像贡献 + 文字贡献"的部分、在完整四行单元上平均时成立；
    预训练的 Qwen 能在语言层形成图文交互，训练用的也是随机小批次，不是每次更新都包含完整单元。
  - B 的事实把判断拆成几步：先抄颜色（文字），再判断"目标或终点在这个颜色的盒子里吗"，最后在写出的事实上做 XNOR。
    但其中随规则翻转的那个包含事实本身也是图文交互（§4.1），所以初稿说的"每一步都有一阶信号"不成立。
  - 反事实平衡没有排除联合捷径：审核时的"颜色统计 × 规则"读数在验证集上 AUROC 约 0.78。
- **对 Phase 2 结论的影响**：
  - "B − A = +29.7 个百分点"仍然成立，新结果说明了这个差距发生在什么背景下；
  - 能说的是"中间监督改善了这种图文联合判断在当前设置下的可训练性"，不能说"直接判别普遍较弱"；
  - 这与 10-17 的评审一致：A 是一个没学起来的基线。它在这个设置下稳定出现，值得作为一个学习现象来研究；
  - 已有理论提供了先例（Wies et al. 2022；Shalev-Shwartz et al. 2017），但其模型、分布和目标条件不能直接套到预训练的 Qwen + LoRA 上。
- **还不能排除的情况**：
  - 只出现在"判定数字紧跟 prompt"这条路径上、目前没看到的问题；
  - 或者 A 只是学得非常慢，160 次更新、学习率 1e-4 不够。
- **预注册规则没有覆盖**"检查后没发现问题"之后该做什么，下一步需要用户决定。

### 4.1 补充分析（2026-10-18，只读训练集与验证集的已有记录，没有新训练）

- **两个包含事实的结构**：
  - 每个图像对里，恰好一个包含事实在两条规则下不变，另一个随规则翻转；256 个训练图像对全部如此。
  - 规则是 XNOR，所以在全部 512 个训练行上，翻转的那个事实都等于判定（不变的事实为 yes 时，256 行）或判定取反（不变的事实为 no 时，256 行）。
  - 也就是说，B 写"Target/Goal inside c:"时学的，正是 A 学不会的那个图文交互；不同的是颜色词就写在答案前面。
  - 不变的那个事实只看图像就能确定，所以按图像查表，每个包含事实能对 75%（复核给出的统计，已复算）。
- **B 的学习顺序**：先学会不变的事实，随规则翻转的事实起初落后，之后追上。

  | 数据与评估点 | 不变的事实 | 翻转的事实 |
  |---|---:|---:|
  | 16 行，第 40 次更新（3 个 seed） | 100 / 100 / 93.8% | 68.8 / 56.3 / 56.3% |
  | 16 行，第 80 次更新 | 100% | 100% |
  | Phase 2 验证集，第 128 步 | 73.4 / 71.4 / 79.2% | 64.6 / 62.5 / 64.6% |
  | Phase 2 验证集，第 256 步 | 89.1 / 81.2 / 84.4% | 91.1 / 76.6 / 90.1% |
  | Phase 2 验证集，第 384 步 | 91.1 / 88.5 / 89.6% | 92.7 / 94.8 / 92.7% |

  第 80 次更新时，3 个 seed 都是 16 行的判定和四个事实全对；第 40 次更新时分别是 11 / 9 / 8 行。
- **参照**：
  - base 模型零样本对"目标/终点在某颜色的盒子里吗"已有一点识别能力，AUROC 0.63 / 0.72（Phase 1 探针）；
  - GPT-6 Luna 零样本直接判断在验证集上有 71.9%，直接判断本身并非做不到。
- **B 也碰到了同样的难点，只是克服了**。候选解释，现在还没有区分开：
  1. 部分一阶信号：不变的事实只看图像就能定，B 先学会的正是这一类；
  2. 颜色词就在答案前面：问题形式接近 base 模型已有的识别能力；
  3. 逐步分解：每个 token 只做一步；
  4. 监督更多：B 每行多了四个事实值 token。

## 5. 下一步：单通路对照（需要用户批准新的训练）

2026-10-18 按独立复核调整。沿用第 1 步的设置：同样的 16 行、同一条 direct 编码路径、同样的超参数，3 个 seed，只换训练目标。

| 对照 | 训练目标 | 结果怎么读 |
|---|---|---|
| 文字标签 t（必做） | `Verdict:` 后写"受保护的是不是橙色"，只看文字就能定 | t 和 s 都学得会、原判定学不会：困难集中在把两者组合起来 |
| 图像标签 s（必做） | 写"分隔盒是不是橙色"，只看图像就能定；原判定正好是 s XOR t | t 或 s 也学不会：继续查实现、优化或输入能否分辨，仍不能直接认定有 bug |
| A+P（建议加） | 先写 `Protected: c`，再写判定；只多抄一个颜色词 | 学得会：瓶颈在把远处的颜色词和图像绑在一起；学不会：还需要中间的包含关系 |
| 梯度测量（可选） | 不训练；在初始化时算这 16 行的逐行判定梯度 | 测完整四行单元内梯度的相消比例，对比判定、t、s 和 B 的事实 token；测过之后才能把"梯度相消"写成机制 |

- 图像标签改用"分隔盒是不是橙色"，不用初稿的"目标在不在橙色盒子里"：s 和 t 正好是判定这个 XOR 的两个因子，检验更干净。
- 初稿里的"A 训练预算 4 倍"暂缓：它只回答"学得慢还是学不会"，不回答机制。
- **预计用量**：约 1.1 A100 小时，一个作业，只用训练集，不调用 API。
