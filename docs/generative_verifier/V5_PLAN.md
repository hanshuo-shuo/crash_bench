## 1. 决定（用户，2026-10-24）

- **不做"收口批"**（四关系＋程序、B 去掉 `Separated`、只预测 `Separated`、A\* 调优）。
  - 前三项的结果基本能从已有结果预判，属于反复验证；
  - A\* 只决定原结论是"学不会"还是"学得慢"，等写论文、审稿人要求时再补（约 1 天）。
- **转向放开 V4 的 toy 之处**，用新环境回答 V4 回答不了的问题。
- **一步步推进**：先只用 CPU、不碰模型做摸底，再决定后面的步骤。

## 2. V4 toy 在哪，V5 要回答什么

| V4 的 toy 之处 | V5 的做法 | 新问题 |
|---|---|---|
| 规则是"保护橙色盒"的颜色模板，程序就能解析 | 规则用自然语言指向场景里的真实物体，物体不在任务文本里出现 | 关系要从语言落到场景时，事实监督还管不管用 |
| 每张图恰好一个分隔盒，判定是一个 XOR | 一个场景同时有多条规则，起分隔作用的有 0、1、2 条 | 组合深度增加时，直接判断与先写事实的差距怎么变 |
| 训练数据刻意平衡成纯 XOR | 训练用自然分布，测试用规则翻转的反事实孪生 | 现实分布下直接训练是否学成捷径、在孪生上出错，事实监督能否避免 |
| 线框画在图上 | 区域由真实物体界定，图像是原生渲染 | 去掉人工标注后，感知是否成为主要瓶颈 |

**保留**：不可行有几何证书，可行有真实安全轨迹见证；规则翻转孪生；按源切分；V4 的锁定测试集不再评估。

**暂不做**：AEGIS 执行区域约束的闭环（需要控制器授权），等 V5 的判断部分站住再说。

## 3. 规则模板草案（由第 1 步检验）

区域都是虚拟的合同约束，不是物理墙。现实中对应工业机器人配置的安全区和禁入区。

| 模板 | 例子 | 不可行证书 | 担心的地方 |
|---|---|---|---|
| **R-line：两物体连线的虚拟墙** | "不要让任何东西越过酒瓶和摩卡壶的连线" | 过两个锚点的竖直平面把目标和终点分在两侧；平面贯穿整个工作空间，是封闭分隔 | 措辞稍显人工；目标或终点离平面太近时看不清 |
| **R-zone：物体周围的区域** | "不要把东西放进或拿出饼干盒周围 10 cm 的范围" | 目标、终点恰有一个在区域柱体内，与 V4 同一证明 | 度量距离很难从图上看出 |

两个模板都不改变场景，图像就是原生渲染。都不合适时，退一步在桌面加平铺的彩色标记。

**锚点只用任务文本里没出现的物体**，否则只读文字就能判断（HazardArena 只给文字就能拦下 92–100%）。

### 第 1 步要回答的问题

1. **文字捷径有多严重**（最先要查）。LIBERO 每个任务的物体初始位置只在很小的区域里变。规则绑在物体上以后，"同一任务＋同一规则"的标签可能几乎不变，只看文字就能猜。
   - 按（任务，规则）统计标签在不同初始状态和 checkpoint 上的分布，算只看文字的上限。
   - V4 靠逐 checkpoint 摆盒避开了这个问题；V5 只能靠初始状态差异，以及搬运过程中目标位置的变化。
2. **标签产出**：每个模板下有证书的不可行候选、未被分隔的候选各有多少；每个状态能否配出规则翻转孪生（一条分隔、一条不分隔）；多条规则时 0/1/2 条分隔的分布。
3. **离边界的距离**：目标、终点到平面或区域边界的距离分布。太近的样本看图判断不了，要排除或单独报告。
4. **锚点核实**：每个 episode 实际摆进工作区的障碍物和干扰物（BDDL 里列了多种障碍物，盘点记录里每个源只有一个 `expected_obstacle`）。

第 1 步只统计几何，不渲染图像、不训练模型。可行候选还需要真实见证，留到第 3 步。

## 5. 第 0 步结果（2026-10-24，只读）

**源的数量**，来自 `verifier_dataset/20261014T055536Z_source-plan_28670c444e49/source_plan/` 和
`20261014T053334Z_inventory_0238a3ac1606/inventory/SUMMARY.json`：

| 项 | 数量 |
|---|---:|
| 官方批次的初始状态（4 个 family × 2 个 level × 4 个任务 × 50） | 1,600 |
| 至少有一次历史 proxy 安全成功（π0.5 或 AEGIS） | **838** |
| 按 family：goal / spatial / object / long | 288 / 229 / 180 / 141 |
| V4 实际用到的源 | 67 条，12 个任务组合（除 object/II/task1 外都是 level I） |

- 838 个状态覆盖全部 32 个任务组合，但分布不均：long/I/task1、long/II/task2、object/I/task2 只有 1–2 个。
- **proxy 安全成功不是接触核验**。每个新源都要先用缓存感知重新执行一次拿到动作带，再过严格的接触回放；选择以历史成功为条件，只为采集效率。
- 已有动作带的：V4 的 67 条，以及 instrumented 池里 33 个初始状态上的 391 条（只覆盖 3 个任务）。

**锚点物体**，来自 `third_party/vlsa-aegis/safelibero/libero/libero/bddl_files/`：

| family | 任务文本会提到的 | 可作锚点（不在任务文本里） |
|---|---|---|
| goal | 碗、盘子、炉灶、抽屉/柜子、奶油奶酪 | 酒架、酒瓶，以及当次的障碍物 |
| spatial | 黑碗、盘子，目标描述里的烤盅（ramekin）/炉灶/木柜 | 饼干盒，未被提到的炉灶、木柜或 ramekin，以及障碍物 |
| object | 目标杂货、篮子 | 其余 4–5 种杂货，以及障碍物 |
| long | 目标物、篮子或盘子 | 其余杂货、杯子，以及障碍物 |

障碍物有 6 种：牛奶、摩卡壶、红咖啡杯、白色收纳盒、酒瓶、黄色书。每个场景至少有障碍物加一个干扰物，R-line 需要的两个锚点都凑得出来。
