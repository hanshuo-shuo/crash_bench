因此 V5 只用手头 V4 的 67 条源，只保留能产出孪生的任务组合，不补源、不扩规模，先把故事从头到尾走通。

## 最小故事闭环

| 步 | 内容 | 资源 |
|---|---|---|
| **S0** | 对 67 条源都试做反事实布局，确定能产出孪生的任务组合和源；检验故事里测试设计的前提 | CPU，本步 |
| S1 | 在反事实布局上渲染一批 Claude 没见过的单元，再盲看一次 | GPU 约 5 分钟 |
| S2 | 训练集用训练源的自然布局，测试集用测试源的反事实孪生；渲染两张对向图 | GPU 1–2 小时 |
| S3 | 训练直接判断（A）和写关系事实（B），先各 1 个 seed 的 pilot，只看验证集 | GPU |

**切分**：沿用 V4 冻结的按源切分（`verifier_dataset/frozen_sources_67.json`）。
- 训练源只出自然布局的行；
- 验证源和测试源出反事实孪生；
- 测试集在任何模型看到之前冻结，只评估一次。
- V4 的锁定测试行不再评估；V5 在同一批测试源上生成的是新任务的新行。

## S0 的做法

- 67 条源，每条 2 个布局，种子为 `sha256(源|布局编号|v5-layout-screen)`；构造、核验和标签与 v3 相同。
- **能力**：一个源只要有一个合法布局在静置时刻产出孪生，就记为可用；一个任务组合只要有一个可用源，就记为可用。
- **捷径迁移检验**，即故事测试设计的前提：
  - 用 C0 里训练源的自然布局行（余量达标）建一张查表：先按（任务，规则，进度段）取多数类，没有对应条目时退到（任务，规则），再退到全局多数类。
  - 用这张表去猜验证源和测试源上反事实静置孪生的标签，报告准确率。
  - 这张表代表"直接判断从自然训练数据里能学到的最好的文字和进度捷径"。

## 读法（事先写定）

- **捷径迁移准确率 ≤ 0.60** → `test_resists_natural_shortcut`：反事实测试能挡住自然数据里的捷径，继续 S1。
- **准确率 > 0.60** → `shortcut_survives`：测试设计要先改，停下来讨论。
- 可用的任务组合和源列表，决定之后 S1–S3 的范围。
- **规模参照**：可用组合中的验证源和测试源少于 4 条时，在报告里标明 S3 只能作方向性判断。

## 资源

`short` CPU 数组作业，4 个分片，134 次回放，预计 20 分钟内。不渲染、不训练、不调 API，不产生数据集行。
