## 0. 一句话

现在的修复（amp2）每个控制步要把 VLM 跑两遍（新指令一遍、旧指令一遍）。用户认为这在真实评测里不实用，想要一个**只跑一遍、不需要旧指令**的版本。

11-12 晚查文献后，这一批的地位变了：中途换指令已有解决办法（Causeway 26.0% → 61.6%），而 amp2 在普查的全部中途状态上只有 22.8% → 26.7%。所以单遍修复当不了"解决方法"，它在论文里是"不训练的做法"那一行和成本数字。

由此得出三条设计约束：

1. **缺的不是"位置"，是"不看旧指令时往哪个方向推"。** 位置已经清楚（第 9–13 层 MLP 写入，第 12–14 层 K/V 读出）。现在所有管用的臂，方向都来自 B − A。
2. **开环筛选只能用来核对工具和定剂量，不能用来预测闭环成败**（H3）。成不成只看闭环。
3. **这一批能回答的是"修复管用的地方，能不能省掉旧指令那一遍"。** 它回答不了"为什么在多数任务对上不管用"。报告里要把这个范围写明。

## 4. 设计

### 4.1 三级台阶

从现有的两遍修复到单遍，中间有两步近似，分开测，哪一步丢了效果就能看出来：

| 级 | 臂 | 参考是什么 | 每次请求的 VLM 遍数 | 回答什么 |
|---|---|---|---|---|
| 0 | `amp2`（已有） | 旧指令 A | 2 | 基准 |
| 1 | `ampmean` | 其余 9 条 Goal 指令的平均（同一张图） | 10 | 不知道 A 行不行。只作上限，不是可用的方法 |
| 2 | `subkv`、`submlp`、`gain` | 事先求好、固定不变的方向和均值 | **1** | 用户要的单遍版本 |

### 4.2 单遍臂

记 x 为某一层某个图像 token 上的向量，μ 为事先求好的均值，P 为事先求好的 r 维子空间的投影，g 为系数。

| 臂 | 位置 | 做法 | 对应用户的话 |
|---|---|---|---|
| `subkv` | 动作头读的第 12–14 层图像 token 的 K 和 V（amp2 的位置） | x ← x + (g − 1)·P(x − μ) | 同一个想法，放在读出口 |
| `submlp` | VLM 第 9–13 层图像 token 上的 MLP 输出 | 同上 | "找到重要的 MLP，eval 时放大"，只放大指令那部分 |
| `gain` | 同 `submlp` | x ← g·x | "找到重要的 MLP，eval 时放大"，整体放大 |

- 三个臂都只跑新指令 B 的一遍前缀，请求里**不带旧指令**。服务端对这三种臂要拒绝带 `prompt_a` 的消息，并且真的只算一次前缀。
- `subkv` 只改动作头读到的缓存，VLM 自己的前向不变（和 amp2 一样）。`submlp`、`gain` 改 VLM 的残差流，下游各层都会受影响。

对照臂（每个单遍臂一个，闭环用）：

| 对照 | 做法 |
|---|---|
| `subkv_rand`、`submlp_rand` | 同样秩的随机子空间，同一个 μ，每次请求把改动的每层范数缩放到与对应臂相同 |
| `gain_off` | 同样的 g 乘在第 2–6 层的 MLP 输出上（位置对照） |

保底臂（用户同意过）：`amp2p1`、`amp2p2`、`amp2p4`、`amp2p8`，即 amp2 只在换指令后的前 N 次请求打开，之后不做任何改动。

### 4.3 方向怎么求

- **数据**：普查正式批次存好的切换点输入。每条前缀（任务 A × 初始布置 0–9）在 f = 0、.5、.75 各有一个状态，输入在分支目录的 `first_policy_input.npz` 里（同一状态的各个 B 只有指令不同，图像和本体状态取一个即可；不同臂之间渲染可能差一个灰度级）。98 条成功的前缀，约 294 个状态。
- **做法**：每个状态用 10 条 Goal 指令各跑一遍前缀（只推理，约 2,940 遍，几分钟）。对每个位置（层 × K 或 V，或层 × MLP 输出）：
  - 指令散布 S_b：同一状态、同一图像 token 上，各指令的向量减去它们的平均，再累加外积；
  - 状态散布 S_w：各状态各 token 的指令平均，减去总均值 μ，再累加外积。
- **两种方向**，都进筛选：
  - `pca`：S_b 的前 r 个特征向量；
  - `lda`：S_b 相对 (S_w + 岭) 的前 r 个广义特征向量，正交化后用。岭取 10⁻³ × trace(S_w) / 维数。它偏向"随指令变、不随画面变"的方向，为的是不带参考时少放大画面内容。
- **留出**：给每个测试对 A→B 单独求一套方向，求的时候**不用**任务 A 的前缀状态，**不用**指令 B。试点三对（1→8、7→8、2→9）各一套。这样闭环测到的是"在别的状态、别的指令上求出的方向，对没见过的 B 管不管用"。
- **秩**：r ∈ {1, 2, 4, 8, 16, 32}。
- 方向文件连同 sha256 写进运行目录和方案；筛选之后、闭环之前冻结，之后不改。

### 4.4 开环筛选

- **状态**：试点开环的 240 个状态（`selection.py`，阶段 1 存档）。定系数只用初始布置 10–19（P4 的读数集）；smoke 用初始布置 0、1。
- **量**：G = 第 12–14 层图像 token 上 K、V 的 B − A 差（与 `neurons.py` 的定义相同）。对某个臂 X 的改动 Δ_X：
  - on = ⟨Δ_X, G⟩ / ‖G‖²。amp2 的 on 恰好是 1。
  - off = ‖Δ_X − on·G‖ / ‖G‖。amp2 是 0，rand2 是 1。
- **定系数的规则**（建议值，写进方案后冻结）：
  - 每个臂族在网格上找"on 的中位数达到 1"的系数。`subkv`、`ampmean` 对系数是线性的，直接解出来；`submlp`、`gain` 用网格 g ∈ {1.25, 1.5, 2, 3, 4, 6}，取 on ≥ 1 的最小 g。
  - 要求 off 的中位数 ≤ 3。依据：rand4 的 off 是 3，在失败格上没有把运行弄坏（28/90 对 native 17/90）；更大的没有数据。
  - 同一族里（`pca` / `lda` × 各个秩）选 off 最小的那个配置。
  - 在 off ≤ 3 之内到不了 on = 1 的，取 on 最大的配置；这个 on < 0.5 就记 `screen_fail`，这一族不进闭环。
- **只报告**：每个臂第一个动作块相对 native 的变化、它在 amp2 动作变化方向上的投影；五个失败格和成功格分开列。不拿它做门槛（H3）。
- **成本测量**：同一张 GPU 上预热后各调用 50 次，报每次请求耗时的中位数：`Policy.infer`、单遍程序、两遍程序（amp2）、十遍程序（ampmean）。这是回答用户"贵多少"的数字。

### 4.5 闭环

- **单位**：重跑阶段 1 的 SW 分支，和闭环、修复批次相同（`closed_loop.py` 的做法，配对、哈希核对都照旧）。smoke 用初始布置 0、1，正式用 2–19。
- **失败格**（五格，90 个状态）：`native`、`amp2`、`ampmean`、过筛的单遍臂及各自的对照、四个 `amp2pN`。最多 13 个臂，1,170 次。
- **成功格 + 起点格**（108 个状态）：`native` 和过筛的单遍臂。最多 432 次。起点格等于"从头到尾开着这个改动做普通任务"。
- 三个单遍族都 `screen_fail` 时不用停：照样跑 `native`、`amp2`、`ampmean`、`amp2pN`，它们回答"不知道 A 行不行"和"要开多久"，并在报告里写明筛选没过。

### 4.6 读法（建议，写进方案第 5 节后冻结；阈值沿用闭环批次）

统计同闭环批次：按 SW 分支配对，按格分层 bootstrap 2000 次、种子 0；增益门槛 0.15，损害门槛 0.10。

| 读法 | 范围 | 判定 |
|---|---|---|
| C1 工具核对 | smoke 和正式 | 闭环批次 C1 的全部条目，另加：单遍程序在不做改动时与 `Policy.infer` 的差（中位 ≤ 0.01，最大 ≤ 0.05）；单遍臂的请求不带旧指令、只算一次前缀；对照臂的改动范数与对应臂之差 ≤ 0.001；`amp2pN` 在第 N 次请求之后改动为 0 |
| P1 单遍能不能救（每个单遍臂 X） | 失败格 | 增益 = X − native，特异性 = X − 它的对照；标签同闭环 R4（`restores_switch` / `weakly_restores` / `nonspecific` / `harms` / `no_restore`） |
| P2 保住多少 | 失败格 | `matches_two_pass`：P1 是 `restores_switch`，且 amp2 − X 的区间上界 ≤ 0.15；`partial`：P1 的增益区间下界 > 0 但没达到前一条；`no_single_pass`：其余 |
| P3 选择性（每个单遍臂） | 成功格 + 起点格 | 同闭环 R5（`selective` / `damages` / `unclear`） |
| P4 不知道 A 行不行 | 失败格 | `ampmean` − native：增益 ≥ 0.15 且区间下界 > 0 是 `a_free_ok`，否则 `needs_a`；同时报告 amp2 − `ampmean` |
| P5 要开多久 | 失败格 | 满足"amp2 − amp2pN 的区间上界 ≤ 0.15，且 amp2pN − native ≥ 0.15、区间下界 > 0"的最小 N：`pulse_enough(N)`；没有：`needs_sustained` |

每个臂各读各的，全部报告，不在事后挑。

解读规则（写在运行前）：
- 某个单遍臂 `matches_two_pass` 且 `selective`：修复管用的地方不需要旧指令那一遍，可以写成"评测时固定打开的一处改动"。
- `ampmean` 是 `a_free_ok` 而单遍臂都不行：不知道 A 是可以的，丢效果的是"固定方向"这一步近似，方向要按状态算。
- `ampmean` 是 `needs_a`：光放大 B 不够，还要减去 A 的成分；任何不知道 A 的单遍做法都不会成，下一步只能考虑知道 A 的做法（比如每条指令事先存一个向量），这要用户另外点头。
- `pulse_enough(N)`：两遍的成本只在换指令后的前 N 次请求出现；同时说明失败主要是"卡在正在做 A 的状态里"。
- 单遍臂只有 `nonspecific`：增益来自扰动本身，不能说找到了指令方向。

**Claude 在 11-12 的预测**（写进方案的"预测"栏）：`ampmean` 是 `a_free_ok` 但低于 amp2；`subkv` 是 `partial`；`submlp` 是 `partial` 或 `no_restore`；`gain` 是 `no_restore` 或 `damages`；`pulse` 至少要 N = 4。

| 做法 | 为什么不做 |
|---|---|
| 只放大少数神经元 | 测过：前 1,000–3,000 名是 31/90，方向不特异；写入是分散的 |
| 按状态调剂量（把印记补回起点的强度，λ = 1/γ） | 普查里最淡的一档（λ = 2 大致正好）增益最小，最不淡的一档（λ = 2 已经过量）增益最大。推广弱不像是剂量不够 |
| 改写提示、输出动作外推 | 测过：25/142、23/142，后者还要多跑一遍 |
| 每条指令事先存一个向量，运行时相加 | 只对见过的指令有用；留到 P4 读成 `needs_a` 时再和用户商量 |
| 微调 | 没有批准，也不是这条线要回答的问题 |

## 9. 做完以后

这一批即使全成，主张的范围也只是"修复管用的那些格"。汇报时把这点和结果放在一起说。

可以向用户提的后续（要点头）：从普查里取 amp2 增益 ≥ 0.3 的非试点格（约 15 格），换新的策略种子，重跑 `native`、`amp2` 和最好的单遍臂，看结论是不是只在试点两对上成立。约 450 次，3 GPU 小时。按格的结果挑格有"赢家偏差"，所以必须换种子、三个臂一起重跑。

其余要用户定的事在 [HIL_METHOD_PLAN.md](HIL_METHOD_PLAN.md) 第 3 节。
